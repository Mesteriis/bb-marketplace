## Итог внешнего аудита

- **Источник:** OCI-образ `mcp/time` на Docker Hub, индекс `sha256:9c46a918633fb474bf8035e3ee90ebac6bcf2b18ccb00679ac4c179cba0ebfcf`; SHA-256 скачанного индекса совпал с закреплённым. Исходники: `modelcontextprotocol/servers`, ревизия `b4ee623039a6c60053ce67269701ad9e95073306`, `src/time` (метка `2025.4.24`, сборка 2025-06-17). Разобрана платформа linux/amd64: манифест `sha256:3bedd9be…`, конфиг `sha256:602d96bb…`, 7 слоёв; SHA-256 конфига и всех слоёв совпали с дайджестами манифеста. arm64 не разбирался.
- **Лицензия:** MIT (метка образа и METADATA пакета). Файла лицензии в слое нет.
- **Запуск и хуки:** `ENTRYPOINT ["mcp-server-time"]`, `WorkingDir=/app`, пользователь в конфиге не задан (root). Скрипт точки входа `/app/.venv/bin/mcp-server-time` (shebang `#!/app/.venv/bin/python`) вызывает `mcp_server_time.main`. Скриптов установки, хуков, подмены `AGENTS.md`/`CLAUDE.md`, автозагрузки навыков нет; это не пакет навыков. `.pth` только штатный `_virtualenv.pth`.

Единственный параметр — `--local-timezone`. Часовые пояса берутся из пакета `tzdata` 2024.2 внутри venv. Сеть коду не нужна: `network: none` подходит.

- **Пересечения:** аналогичных навыков в Engineering Bible нет.

- **Права пользователя (по заголовкам tar):** песочница задаёт uid 65534, и **это не работает**. Интерпретатор — симлинк `/app/.venv/bin/python -> /root/.local/share/uv/python/cpython-3.10.18-linux-x86_64-gnu/bin/python3.10`, а каталог `/root/` в итоговом слое — `drwx------ root:root` (0700; тот же режим в базовых слоях). Пользователь nobody не пройдёт через `/root`, `python3.10` не запустится, `mcp-server-time` не стартует. Сами файлы приложения (`/app`, `/app/.venv/...`) читаемы всеми (0755/0644), скрипт точки входа 0755. Поэтому в entry.json стоит `"docker": {"user": "image"}`. Сеть остаётся `none`, корень read-only и сброс capabilities ограничивают риск от root в контейнере.
- **Проверка:** манифест, конфиг и слои сверены по SHA-256; прочитаны история сборки, `server.py`, `__init__.py`, точка входа, `pyvenv.cfg`, список dist-info, режимы и владельцы в tar. Код не исполнялся, реальный старт под uid 65534 и под root в рантайме не проверялся (вывод о `/root` сделан по режимам в слоях).

## Находки и риски

1. **Средний (совместимость).** Интерпретатор лежит в `/root` с правами 0700, под nobody образ не запустится. Устранено исключением `user: image`.
2. **Низкий.** Образ работает от root (в конфиге нет `User`). Смягчается: `--network none`, read-only корень, tmpfs `/tmp`, сброс всех capabilities.
3. **Низкий.** Устаревшие зависимости: `mcp 1.0.0`, `starlette 0.41.3`, `uvicorn 0.32.1`, `certifi 2024.8.30`, `pydantic 2.10.2`, `anyio 4.6.2.post1`, `httpx 0.28.0`. По stdio серверная HTTP-часть не используется; уязвимости по базе не сверялись.
4. **Информационно.** Пакет собран на Python 3.10.18 (uv, в `/root/.local`) поверх базового Python 3.12.11 — два интерпретатора, лишний вес.
5. **Информационно.** Запись реестра не задаёт переменные окружения и аргументы; `repository.url` указывает на ту же ревизию, что и метка образа. Лицензия подтверждена только метаданными.
