# Проверка: com.atlassian/atlassian-mcp-server, версия 2.0.0

Чек-лист: external-agent-pack-audit. Это облачный сервер без пакета и образа: скачивать и запускать нечего. Код сервера недоступен для чтения, проверены запись реестра и README с лицензией из репозитория (скачаны как данные во временную папку вне рабочего дерева, ничего не запускалось).

## Итог внешнего аудита

- **Источник:** запись реестра `com.atlassian/atlassian-mcp-server` 2.0.0, репозиторий `github.com/atlassian/atlassian-mcp-server` (ветка main, неизменяемая ревизия не закреплена). Два удалённых endpoint типа `streamable-http`: `https://mcp.atlassian.com/v2/mcp` (индекс 0, рекомендован README) и `https://mcp.atlassian.com/v1/mcp/authv2` (индекс 1, прежнее поколение). Пакетов (npm, OCI, pypi) в записи нет.
- **Лицензия:** Apache 2.0 (LICENSE репозитория). Относится к материалам репозитория (навыки, плагины, документация); серверный код на стороне Atlassian закрыт и подчиняется условиям сервиса Atlassian.
- **Запуск и хуки:** локального кода нет, значит нет скриптов установки, хуков и подмены `AGENTS.md`/`CLAUDE.md` из самого сервера. README описывает необязательные пути: `mcp-remote` через npx (сторонний npm-пакет, в проверку не входит) и плагины/навыки из репозитория (`skills/`), которые в этой записи не используются. Версия сервера на стороне Atlassian меняется без нашего ведома: закрепить её нельзя.
- **Секреты и сеть:** все данные уходят на `mcp.atlassian.com`. Вход: OAuth 2.1 (браузер) или API-токен (`Authorization: Basic base64(email:token)`, нужно включение администратором). Для Jira Service Management работает только токен. Токен не должен попадать в файлы проекта и логи.
- **Инструменты:** группы разрешений по продуктам: Jira, Confluence, Bitbucket Cloud, JSM, Teamwork Graph, Loom, Goals, Projects, Teams, Focus, Talent, Compass; у каждой есть read/write/search, у Jira ещё `delete_jira` и `manage_jira` (выключены по умолчанию, включает администратор). Есть запись и удаление данных. Полный список инструментов не проверялся.
- **Пересечения:** в Engineering Bible аналогов нет; сервер охватывает Jira/Confluence/Loom/Bitbucket/Compass.
- **Решение:** принять как **managed upstream install** только в виде удалённого endpoint `index 0` (`/v2/mcp`) с минимальными правами. Endpoint `/v1/mcp/authv2` не выбирать: прежнее поколение, README сам рекомендует v2.
- **План адаптации:** OAuth 2.1 вместо API-токена; права урезать до чтения (`read_*`, `search_*`), группы `write_*` включать по задаче; `delete_jira` и `manage_jira` не включать. Подключать без `?tools=all`. Не передавать содержимое Jira/Confluence в сторонние сервисы.
- **Проверка:** прочитаны запись реестра, README и LICENSE; соединений с `mcp.atlassian.com` не открывалось, инструменты не вызывались, поведение в рантайме не проверялось.

## Находки и риски

1. **Средний.** Содержимое задач, страниц и комментариев Jira/Confluence пишут люди, в том числе внешние; это канал косвенной инъекции подсказок (сам README это признаёт). При включённых `write_*` инъекция может привести к изменению данных. Смягчение: права только на чтение по умолчанию, подтверждение записей человеком.
2. **Средний.** Серверный код закрыт и обновляется Atlassian без версионирования для клиента: поле `version` 2.0.0 не фиксирует поведение. Закрепить ревизию нельзя.
3. **Низкий.** Запись содержит два endpoint; индекс 1 (`/v1/mcp/authv2`) устаревшего поколения. README: v1 продолжает работать и получает инструменты v2, старый `/v1/sse` перестал поддерживаться после 30.06.2026.
4. **Низкий.** API-токен (Basic) даёт доступ без браузерного входа; при утечке права равны правам пользователя. Предпочесть OAuth.
5. **Информационно.** Запись реестра не задаёт заголовки и переменные окружения. IP-ограничения организации действуют и для вызовов через сервер; со стороны размещённых клиентов возможны ответы 403.
6. **Информационно.** Ссылка `websiteUrl` ведёт на документацию Atlassian; её содержимое не проверялось.
