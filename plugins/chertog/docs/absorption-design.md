# Чертог поглощает навигацию и список тредов — дизайн

Дата: 2026-11-22. Статус: на согласовании владельцем.

## Зачем

Владелец хочет один плагин вместо трёх. Чертог становится рабочим местом BB из
отдельных частей, каждую из которых можно включить и выключить в настройках
Чертога. Две из них сейчас живут в отдельных плагинах — Makosh Navigation
(`plugins/navigation`, ID `makosh-navigation`) и Makosh Sidebar
(`plugins/sidebar`, ID `makosh-sidebar`). Чертог поглощает их целиком: их
поведение остаётся на всех экранах BB, а не только на странице Чертога.
Исходный повод — клик по треду в списке «Сейчас / Проекты» должен добавлять тайл
в Чертог.

## Части Чертога

| № | Часть | Где видна | Чем является сейчас |
|---|---|---|---|
| 1 | Навигация | штатное место навигации BB, все экраны | Makosh Navigation (`experimental_sidebarNavigation`) |
| 2 | Список тредов «Сейчас / Проекты» | штатное место списка тредов BB, все экраны | Makosh Sidebar (`experimental_threadList`, `experimental_threadAction`) |
| 3 | Тайловое пространство | страница Чертога | Чертог этапов A–C |
| — | Кастомизация `ThreadChat` | тайлы треда | заглушка без поведения; отдельный будущий проект |

Каждая часть — переключатель в настройках Чертога и свои настройки. Выключенная
часть не регистрирует свою поверхность BB (штатная навигация или список BB
возвращаются).

`ThreadChat` — обычный тайл, а не отдельная часть: на одном пространстве живёт
сколько угодно тайлов треда. В тайле может жить любая сущность, которая в BB
занимает центральную часть экрана; живьём — только то, для чего у SDK или у
плагина-владельца есть способ встраивания (сейчас: тред, файл, diff, терминал,
Telegram, Zoom, Remote Hub). Остальное — карточка, открывающая штатный экран,
и узкое предложение хосту (как в `discovery-providers.md`).

## Решения владельца

- Путь поглощения **А**: код Navigation и Sidebar переезжает в `plugins/chertog`
  отдельными модулями со своей логикой и тестами; старые плагины удаляются после
  переноса данных. Временное отключение на время переезда допустимо.
- Подчинённость тайлов — вариант **Б, связанный блок**: подчинённые тайлы стоят
  рядом с основным, блок переносится, разворачивается, сворачивается и
  закрывается целиком. Сверх трёх подчинённых — вкладками в последнем тайле блока.
  Подчинённые: субтреды основного треда и сущности, открытые из него (например RDP).
  Два самостоятельных треда — два независимых тайла.
- Клик по субтреду в списке, когда тайл основного треда открыт, — субтред
  встаёт в блок основного. Когда основной тред не открыт — открывается только
  субтред, самостоятельным тайлом. Родитель субтреда берётся из дерева тредов BB
  в момент открытия; для сущностей, открытых из тайла, родитель — этот тайл.
- `ThreadChat`: в Чертоге заглушка, кастомизацию делаем отдельно. Плагин
  `beautiful-chat` отключён 2026-11-22; остальные плагины треда (genui,
  impromptu-ui, inline-vis, image-preview, inline-review, prompt-library, drafts,
  dictation-shortcuts, agent-annotations) остаются до того проекта.
- Порядок проектов: 1 → 2 → 3 → 4 (ниже).

## Проекты по порядку

1. **Клик в списке → тайл; связанные блоки.** На странице Чертога обычный клик
   по треду в части 2 (строки «Сейчас», «Проекты», «Требует внимания»)
   добавляет тайл треда; если тред уже открыт — фокус на его тайл. Вне страницы
   Чертога клик работает штатно; Cmd/Ctrl/Shift/Alt-клик — всегда штатно.
   Субтреды основного треда и сущности, открытые из его тайла, получают отметку
   родителя и встают в его блок. До проекта 2 список ещё в `makosh-sidebar`,
   поэтому сигнал идёт событием в документе (`chertog.open.v1`, как
   `chertog.embed.v1`: Чертог отвечает, принял ли; не принял — штатный переход).
   После проекта 2 это внутренний вызов, событие удаляется.
2. **Поглощение Sidebar.** Переезжают список «Сейчас / Проекты», фильтры,
   «Требует внимания», скрытие, контекстные действия треда и движок
   `plan_progress` (инструмент агентов, CLI `bb plan-progress`, полоска над
   вводом, диагностика, напоминания). Данные переносятся через существующие RPC
   `progress_export`/`progress_import` и чтение `kv`-настроек до удаления
   `makosh-sidebar`.
3. **Поглощение Navigation.** Переезжают группы, иконки, разделители, редактор с
   автосохранением, вкладки «Сейчас / Проекты» в верхней области. Раскладка
   переносится через RPC `read` плагина `makosh-navigation` до его удаления
   (данные в его `data.db`).
4. **Новые сущности в тайлах.** Браузер BB (`experimental_desktopBrowsers`) и
   далее по одной; для невстраиваемых — карточка и предложение хосту.

## Ограничения

- `AGENTS.md`: `src/core` и `src/ui` без кода хоста; без импортов между
  каталогами плагинов; `bb.description`, `PLUGIN_OVERVIEW.md` и запись
  `marketplace.json` описывают текущее поведение и меняются вместе; перенос
  кода — с записью в `THIRD_PARTY_NOTICES.md`, если код не наш.
- Проверка на изолированном стенде (`e2e-stand.md`); установка в рабочий BB,
  push и удаление старых плагинов — с разрешения владельца.
- ID инструмента `plan_progress` и команда `bb plan-progress` не меняются:
  на них ссылаются инструкции агентов.

## Не цели

- Свой `ThreadChat` и перенос плагинов треда (отдельный проект).
- Встраивание штатных экранов BB без API хоста (только карточка и предложение).
- Изменения хоста BB.

## Анти-цели (провал, даже если работает)

- Потеря раскладки навигации, скрытых проектов и тредов, истории `plan_progress`.
- Двойной список или двойная навигация на экране.
- Клик в списке молча уводит со страницы Чертога, когда тайл можно было добавить.

## Подходы, которые рассматривали

- **А (выбран).** Код переезжает в Чертог модулями, старые плагины удаляются после
  переноса данных: один плагин и одна точка настройки.
- Б. Старые плагины остаются, Чертог управляет ими событиями — не поглощение,
  три установки.
- В. Как А, но старые плагины временно живут параллельно — два источника правды.

## Решения исполнителя (по проверке документа, владелец может поправить)

- **`plan_progress` — отдельная часть «Прогресс планов»** со своим
  переключателем, а не часть списка тредов: выключение списка не должно
  убирать инструмент, которого требуют инструкции агентов. По умолчанию включена.
- **Переключение части** может требовать перезагрузки Чертога (поверхности
  регистрируются при загрузке приложения плагина); на свежей установке и после
  переноса все части включены.
- **Перенос данных**: RPC старых плагинов вызываются через
  `bb.sdk.plugins.callRpc`; их настройки хоста — через
  `bb.sdk.plugins.getSettings`; скрытые проекты и треды Sidebar лежат в
  `localStorage` (`makosh-sidebar:hidden:v1`) того же документа и копируются
  приложением Чертога. Перенос идемпотентен и выполняется до удаления старых
  плагинов.
- **Сессии агентов при переезде `plan_progress`**: запускатель Claude живёт в
  каталоге данных `makosh-sidebar`; при переезде идущие сессии допускается
  перезапустить (владелец согласен на временное отключение). Навык
  `skills/plan-progress` сохраняет имя.

## Оставлено исполнителю

Внутреннее устройство модулей, форма отметки родителя в документе раскладки,
порядок и формат переноса данных, тексты настроек, тесты и стенд.
