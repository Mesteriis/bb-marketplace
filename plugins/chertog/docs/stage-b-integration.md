# Этап B. Что можно показать в тайле Чертога

На BB 0.50.1 и SDK **0.6.157** штатные экраны Telegram, Zoom, Remote Hub, Terminals, Markdown Editor, Diff Review и App Preview открываются у владельца. В тайле можно разместить карточку перехода. Для содержимого BB есть более сильные контракты: просмотр файла и однофайловый diff хост умеет рисовать непосредственно внутри компонента плагина. Для приложения, которое разрешает встраивание, возможен отдельный iframe с его веб-страницей. Существующая вкладка браузера при этом остаётся отдельным экземпляром.

Исследованы декларации именно установленного пакета 0.6.157 и код на базе `3116fa3e`. Дальше указаны границы реализации и сценарии для проверки. По этой работе **все результаты на живом провайдере — не проверено**. Карточки и имена новых типов ниже предложены для этапа B. Для существующего треда публичный ThreadChat принимает threadId и layout="contained". Чужой navPanel или его контекст вкладки через него передать нельзя (app 23752, 24863). Образцы зарегистрированных поставщиков — [thread-source.ts](../src/adapters/bb/app/thread-source.ts) и [fixture-source.tsx](../src/adapters/bb/app/fixture-source.tsx). Основания и критерии — [предыдущее обследование](discovery-providers.md), [пин версии](sdk-version.md), [задание, разделы 3–5](spec.md).

## Способ открытия из рабочего поля

| Операция в SDK 0.6.157 | Где действует и что можно подтвердить |
|---|---|
| Ссылка на `/plugins/<pluginId>/<path>/*` | Форма публична в `PluginNavPanelProps` (bundled-types/bb-plugin-sdk-app.d.ts, далее **app**, строки 19571–19584). Для карточки — обычная ссылка на фиксированный зарегистрированный маршрут текущего BB, сегменты адреса кодирует адаптер. Сначала пользователь явно открывает раздел. Сохранение документа overlay при клике по обычной ссылке, обработка back и открытие на Desktop — не проверено. Риск полной навигации важен для уже открытых живых панелей. До проверки безопасен ручной переход штатным пунктом BB. Не помещать целое приложение BB в iframe. |
| `experimental_useSidebarNavigation().actions.activate(itemId, {target})` | Компонент в sidebar получает ID вида `<pluginId>/<panelId>` и флаги `isLoading/isDisabled`. Вне sidebar список пуст, действия ничего не делают. `activate` возвращает void, аргумента subPath нет. `split` у лимита заменяет активную панель, при compact может открыть вкладку. `tab/split` требуют синхронного жеста. Для кнопки рабочего поля этот хук непригоден (app 19739–19803, 24705–24711). |
| `useBbNavigate().toPluginPanel(path,{subPath})` и `experimental_useAppPanel().openTab` | Первое открывает navPanel вызывающего плагина, второе работает с его зарегистрированными вкладками. Это объясняет, почему вызовы из Zoom/Remote Hub/Diff Review нельзя копировать в Чертог с чужим ID (app, `BbNavigate`, `ExperimentalTabReference`). |
| `experimental_openFilePreview({target,location:null})` | Открывает общий просмотр файла. Без `opener` BB применяет настройку пользователя. Явный `opener` выбирает регистрацию вызывающего плагина. Если такой регистрации нет, используется просмотр BB. Для выбранного внешнего редактора есть `experimental_openFileExternally` (app 24095–24140, 24333–24336). |
| `experimental_openTerminal({terminalId})` | Выбирает или добавляет вкладку существующего терминала и раскрывает штатную панель. На странице плагина допустим любой терминал, в треде — его собственный. Для отсутствующего/завершённого терминала или поверхности без панели возвращает false. Закрытие вкладки завершает терминал (app 24337–24350). |
| `useSdk().experimental_desktopBrowsers.revealTab` | На выбранном хосте запросить `listInstances({hostId})`. Для выбранного экземпляра и треда вызвать `listTabs({hostId,instanceId,generation,threadId})`. После явного выбора вкладки передать этот же набор полей и её `tabId` в `revealTab`. Вызов адресует существующую вкладку, не требует control lease и возвращает `{ok:true}` при успехе. У `openUrl` входом служит URL, выбрать конкретную вкладку им нельзя (app 17179–17194, 17792–17803, 19474). |
| `openUrl(url)` | HTTP(S) открывается по настройке браузера клиента. true означает, что запрос обработан. Метод не предоставляет DOM, tabId, WebContents, статус загрузки или право удержания (app 24325–24332). |
| `useRpc()` и `useSdk().plugins.callRpc({pluginId,method,input,outputSchema})` | Первый клиент привязан к своему плагину. Второй **доступен фронтенду**: `PluginBrowserBbSdk` включает `PluginsArea`, запрос выполняется с сессией пользователя. Есть `experimental_discoverRpc`. Сервер получает `experimental_caller` и может отказать. Публикация схемы не делегирует авторизацию, не создаёт вид и не отменяет подтверждение. Сырые HTTP-вызовы для получения статуса client, прокси серверной стороны Чертога и подмена адресата исключены (app 18381–18386, 18470–18479, 20955–20965, 24487, 24819; bb-plugin-sdk.d.ts 20835–20849). |

## Ссылка, возможности и время жизни

Запись имеет форму `{provider, params}`. Здесь фигурные скобки обозначают **закрытый** `paramsSchema` (`z.strictObject` либо объединение таких объектов). `{}` принимает ровно пустой объект. Идентификаторы — непустые строки из явного выбора доверенного каталога, с ограничениями [panelRefSchema](../src/core/panels/ref.ts). Все примеры — схемы, без пользовательских значений. Минимальная ссылка ведёт только туда, куда действительно может перейти адаптер.

Вектор возможностей дан в порядке [PanelCapabilities](../src/core/panels/provider.ts): штатный маршрут / конкретный вид в тайле / удержание в документе / перепривязка к существующей сессии / межоконная передача / разрешение ссылки после рестарта. Обозначения: **Д** — yes по контракту, **Ч** — partial с указанной границей, **Н** — no для данного адаптера, **?** — unverified. У карточек последние два слова «восстановить ссылку» означают возврат точки входа. У статического просмотра восстановим выбранный ресурс, если он ещё доступен. Поведение текущей внешней сессии не выводится из состояния карточки.

**Две системы идентификаторов вкладок.** У App Preview параметр tabId — ID записи в списке `threads.tabs.get({threadId})`. Desktop выдаёт собственный tabId через listTabs в области конкретного экземпляра и поколения. SDK не устанавливает соответствия между этими ID. Для карточки Desktop выбранную тройку instanceId/generation/tabId держим в памяти окна. При смене поколения, закрытии вкладки или после рестарта предлагаем повторить выбор. Сохранённые hostId и threadId восстанавливают область поиска. Автоматического перехода к совпавшему URL нет.

**Схема F.** Минимальный вариант для этапа B — `{kind:"workspace",environmentId,path}`. Полный `ExperimentalLiveFileTarget` допускает отдельные строгие варианты host + hostId и thread-storage + threadId. Путь хранить как проверенный идентификатор ресурса с кодированием пробелов по правилам PanelRef. При открытии декодировать один раз и проверять относительно соответствующего корня, включая выход через сегменты пути. Для diff ограничить SHA полными Git SHA-1 и принимать пути в выбранной среде. Для Diff Review контракт провайдера допускает больше целей, чем минимальные две в таблице. Для расширения нужен свой закрытый вариант для каждой цели и её параметров. Кодек провайдера кодирует JSON цели как сегмент, затем сегмент маршрута ещё раз. Произвольную строку subPath из сохранённой раскладки не передавать.

**Состояние карточки.** Видна доступность раздела или файла и результат последней попытки открытия. Тайлу нужен отдельный признак «точка входа»: у текущего PanelProvider результат open со статусом live означает подтверждённый вид. Карточку можно честно пометить «готова к открытию», а статус внешней сессии оставить неизвестным. При отказе, отсутствии плагина, пропавшей цели или неизвестном исходе показать причину, сохранить ссылку, дать повторить вручную. У карточек addressee=null, multipleViews=false, release освобождает только карточку, endsSessionOnLastClose=false, команда endSession скрыта. Клик по карточке и восстановление раскладки не подтверждают участие, подключение или отправку. Для загруженного файла или diff состояние live относится лишь к видимому рендереру. Получатель вложения определяется отдельным явным выбором существующего черновика. Drop, перестройка и restore не посылают сообщение.

## Почему чужие HTTP и RPC не дают живой экран

- **Telegram.** Весь экран с папками, чатом и деталями собран на navPanel и порталах. HTTP обслуживает медиа, экспорт, файлы и кадры звонка, Mini App имеет собственный iframe. Ни один из этих ответов не рисует переписку. RPC обёрнут guard для всех методов, discoverable выключен. Смену глобального аккаунта для имитации двух панелей исключить. [Страница](../../telegram/app.tsx), [кадры](../../telegram/src/adapters/bb/private-call-frames.ts), [регистрация RPC](../../telegram/server.ts).
- **Zoom.** GET `/call` внутри HTTP-префикса Zoom без ticket отдаёт оболочку Meeting SDK. Родитель Zoom передаёт подготовленную встречу в iframe через postMessage после его готовности. В другом режиме `/call?ticket=…` обменивает одноразовый билет со сроком две минуты, повтор даёт 410. Подготовка использует подпись Meeting SDK и при необходимости ZAK. Общий вызов callRpc технически возможен, но контракт делегирования звонка Чертогу не объявлен. Чертог не запрашивает PreparedCall или билет и не сохраняет invite URL. [HTTP](../../zoom/src/adapters/bb/http-routes.ts), [билеты](../../zoom/src/adapters/bb/call-tickets.ts), [подготовка](../../zoom/server.ts), [протокол iframe](../../zoom/src/ui/call-panel.tsx).
- **Remote Hub.** Консоль рисует фронтенд владельца. `/attach` — WebSocket, принимающий выданный session_attach одноразовый токен на 30 секунд для пары generation/sessionId. Обёртка ownerOnly закрывает и выдачу билета, и список сеансов от вызывающего плагина. Навигация владельца допускает временный subPath с ключом уже живой сессии. В раскладке хранится нейтральная точка входа; профиль или VM можно добавить, когда владелец предоставит их каталог и безопасный маршрут. Секретов, attach-токена, sessionId и поколения helper в PanelRef нет. [RPC](../../remote-hub/src/adapters/bb/rpc-handlers.ts), [транспорт](../../remote-hub/src/adapters/bb/stream-socket.ts), [штатный вызов](../../remote-hub/app.tsx).
- **Terminals, Markdown Editor, Diff Review.** Все три рисуют HTML средствами React внутри слота BB. У Terminals сокет передаёт байты терминала. GET `/asset` Markdown Editor отдаёт ресурс. Diff Review получает данные и комментарии через RPC; чужая выдача патча не переносит штатный экран ревью. Отдельного HTTP-документа интерфейса для iframe в их регистрациях нет. SDK предоставляет данные BB-терминала (get/output/input/resize) и файла (read/write с expectedSha256). Написать отдельный терминальный клиент или редактор возможно, но его собственные буфер, обработка конфликтов, replay и право ввода потребовали бы отдельной реализации и приёмки. Для штатных видов выше предложены операции BB.
- **App Preview.** `inspect(threadId)` возвращает openUrl вместе с командой и logTail. При активном процессе он также обновляет журналы и синхронизирует вкладку браузера. Фоновый опрос чужого inspect для карточки не подходит. Публичен `useSdk().threads.tabs.get({threadId})` (app 19316–19319): из уже выбранной пользователем вкладки типа browser можно разрешить URL заново по её ID; список сам по себе не удостоверяет принадлежность вкладки App Preview. Для явного открытия доверенной тестовой страницы без билетов/секретов проверить схему, origin и возможность frame-ancestors/X-Frame-Options, mixed content и sandbox на конкретном стенде. Только при подтверждённой загрузке целевой страницы (для подконтрольной страницы — сигнал готовности с проверкой origin и окна) показывать живой iframe под постоянным родителем. Событие load само по себе недостаточно. Если встраивание не подтверждено, оставить карточку с явным openUrl. Не сохранять порт, raw URL, токены, логи и не запускать сервер при restore. [RPC](../../app-preview/server.ts), [inspect и синхронизация](../../app-preview/service.ts), [запись вкладки](../../app-preview/browser-tabs.ts).

Это предложения, требующие отдельных изменений. Базовая операция хоста общая для строк, которым нужен чужой слот.

| Где | Что передаётся и кем исполняется | Критерий теста |

Никаких учетных данных или RPC полномочий родителю. Отдельная операция навигации с pluginId/path/subPath из overlay, с отказом при нехватке места, достаточна для SPA-карточек. | Два плагина: при смене прямоугольника один mount, прежний DOM и scope. При disable вид отозван. У лимита защищённый тайл на месте; back сохраняет документ. |

## Граница приёмки

На [изолированном веб-стенде](e2e-stand.md) достижимы проверки перехода к целевому разделу, выбора файла, вывода однофайлового diff, открытия существующего терминала и сохранения ссылки при отключении провайдера. Для каждого сценария открыть через карточку, вернуться, изменить split, переключить пресет и перезагрузить. Проверить соответствие цели и отсутствие повторного доменного действия. Для условного iframe использовать тестовое приложение с собственным boot ID и второе с запретом встраивания. Результаты по этим сценариям — **не проверено**.

| Строка раздела 5 | Что можно доказать на текущем интерфейсе | Что остаётся открытым и как проверить |
|---|---|---|
| Браузер и Zoom | Штатный переход к календарю, открытие URL и отдельный адресный переход Desktop. Открыть две вкладки с одним тестовым URL, выбрать вторую через listTabs и проверить, что revealTab показал именно её. Это проверяет выбор вкладки. Удержание и сохранность документа требуют отдельного прогона. | **Не проверено.** Desktop с контрольной и удерживаемой вкладкой, штатный проход выгрузки, сравнить WebContents ID и boot ID до/после и после освобождения. В разрешённой встрече второй клиент проверяет участие и медиа по сценарию Zoom выше. Для плеера отдельно проверить позицию и единственный звук. |
| Telegram | Достижим переход на один полный экран Telegram. | **Не проверено.** Два тестовых адресата, несохранённый ввод, выделение, прокрутка, перенос, смена схемы и входящее событие. До адресуемого экземпляра два чата в тайлах остаются открытой строкой. |
| BB-терминал и Remote Hub | BB может открыть терминал по его ID. Remote Hub открывает штатный экран, переподключение разрешает сам провайдер. | **Не проверено.** На разрешённой тестовой сессии сохранить session ID и PID, вывести нумерованные строки до, в фоне и после resize, проверить ввод, границу replay и пропуски. Отдельно выполнить RDP и VNC проверки из таблицы адаптеров. Карточка не наблюдает PTY и lease. |

Пресеты «Команда агентов», «Администрирование» и «Созвон» могут сохранять ссылки и расстановку карточек наряду с живыми тредами. Само появление карточки в пресете не закрывает ни одну из трёх строк приёмки.
