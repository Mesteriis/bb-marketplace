# Чертог: перенаправление штатного Home

Решение владельца: «скрыть стандартный Домой; если пользователь случайно туда попадает, сразу перенаправлять на Чертог». Оно отменяет отказ от перенаправления в [discovery-home.md](discovery-home.md) (раздел «Вывод для этапа A»). Остальные выводы того отчёта остаются в силе: публичной замены Home в SDK нет, и узкий патч хоста из раздела «Пробел хоста» по-прежнему был бы точнее этого обхода.

Состояние на 21.11.2026: правило, адаптер и тесты написаны, в `app.tsx` ещё не подключены (подключение и объявление настройки делает другой срез). В запущенном BB ничего из этого не проверялось.

## Что делает

Перенаправляется одно событие: пользователь оказался на экране нового треда по корневому адресу `/`, и ничто не говорит, что он шёл туда намеренно. Тогда BB переходит на `navPanel` Чертога с `replace: true`: запись Home в истории заменяется записью Чертога.

Во всех остальных случаях штатный экран остаётся, и секция Чертога показывает на нём одну кнопку «открыть Чертог».

| Факт | Откуда берётся | Результат |
|---|---|---|
| Настройка выключена | параметр `useRedirectEnabled` вернул `false` | остаёмся |
| Настройка ещё не загружена | `useRedirectEnabled` вернул `null` | ждём, штатный экран остаётся; решение принимается, когда значение придёт |
| Есть одноразовый пропуск | собственное действие Чертога «Новый тред» | остаёмся, пропуск потрачен |
| В маршруте есть проект | проп `projectId` секции не `null` | остаёмся |
| Экран нового треда — панель split | `useSidebarSplitLayout()` не `null` | остаёмся |
| Ничего из перечисленного | | переход на Чертог, один раз |

Любое сомнение оставляет штатный экран: ошибка в факте стоит пропущенного перенаправления, а не потерянного экрана нового треда.

## Как устроено

**Сигнал «это штатный Home».** Хост монтирует `homepageSection` только на экране нового треда, он же Home по умолчанию. Секция Чертога сама и есть датчик: раз её компонент отрисован, экран показан. Другого публичного признака маршрута у плагина нет.

**Проект.** В установленном BB 0.50.1 `projectId` секции приходит из маршрута `/projects/:projectId/*`, на корневом `/` он равен `null` (проверено чтением собранного `root-compose-*.js` и `index-*.js`, не запуском). Поэтому экран нового треда, открытый для проекта, не перенаправляется.

**Одноразовый пропуск.** Экран нового треда и Home — один маршрут, поэтому намерение Чертог сообщает сам: `openNewThreadScreen(navigate, options)` сначала выдаёт пропуск, потом вызывает `toCompose`. Первое же появление секции тратит пропуск. Пропуск живёт в памяти окна 5 секунд (`NEW_THREAD_PASS_TTL_MS`): если переход не состоялся, он не достанется следующему случайному Home. Перезагрузка окна и другое окно начинают без пропуска.

**Одно решение на посещение.** Посещение длится от появления секции до её исчезновения. За посещение пропуск берётся один раз и решение принимается один раз, повторные рендеры и StrictMode второго перехода не дают. Если хост в одном обновлении снимает секцию и монтирует заново (например, при смене компактной и широкой раскладки), это то же посещение: конец посещения откладывается на `queueMicrotask` после размонтирования. Экран, пропущенный по пропуску, не перенаправится из-за такой перестройки.

**Нет цикла.** Переход ведёт на маршрут панели плагина, где секция не монтируется, значит наблюдать больше нечего. `replace` убирает запись Home из истории, «назад» с Чертога попадает на экран, который был до Home. Если переход почему-то не увёл с экрана, повторного вызова не будет: посещение уже решено, и секция покажет кнопку.

## Файлы

- `src/core/home/decision.ts` — `decideHomeRedirect(facts)`, чистая функция.
- `src/core/home/new-thread-pass.ts` — пропуск: `grant(now)`, `consume(now)`.
- `src/core/home/presence.ts` — учёт посещения: `enter`, `leave`, `settle`, `observe`.
- `src/adapters/bb/home/controller.ts` — превращает решение в один `toPluginPanel(path, { replace: true })`.
- `src/adapters/bb/home/facts.ts` — факты из пропсов и хуков SDK.
- `src/adapters/bb/home/new-thread.ts` — `allowNextNewThreadScreen()`, `openNewThreadScreen(navigate, options)`.
- `src/adapters/bb/home/HomeRedirectSection.tsx` — `createHomeRedirectSection(options)`.

Используются только `useBbNavigate`, `useSidebarSplitLayout` и проп `projectId` из `@get-bb/plugin-sdk/app` (SDK 0.6.157). Приватных импортов хоста, записи под ключи BB, `localStorage`, чтения или изменения DOM хоста нет.

## Подключение (делает другой срез)

```tsx
import { useSettings } from "@get-bb/plugin-sdk/app";
import { createHomeRedirectSection } from "./src/adapters/bb/home/index.ts";

app.slots.homepageSection({
  id: "chertog-home",
  title: "Чертог",
  component: createHomeRedirectSection({
    panelPath: "home", // path зарегистрированной navPanel Чертога
    openLabel: "Открыть Чертог",
    useRedirectEnabled: () => {
      const { values } = useSettings();
      return values === undefined ? null : values.replaceHome === true;
    },
  }),
});
```

`createHomeRedirectSection` вызывается один раз на приложение плагина. Имя настройки `replaceHome` здесь условное. Действие «Новый тред» внутри Чертога должно идти через `openNewThreadScreen(useBbNavigate(), options)`, иначе его экран будет перенаправлен обратно.

## Что скрывается

Ничего. Публичного способа скрыть штатное содержимое Home или кнопку «Домой» нет, обход не делался.

- Слота или настройки, убирающих содержимое экрана нового треда, в SDK 0.6.157 нет.
- Content script (`app.contentScripts.register`) может подключить таблицу стилей, как это делает `plugins/ultragoal` для строк тредов. Но там селектор опирается на атрибут, описанный в контракте SDK. Для кнопки «Домой» и для содержимого экрана нового треда такого атрибута нет: в типах SDK упомянуты `data-sidebar-thread-shortcut-target`, `data-question-form`, `data-promptbox-*`, `data-changed` и `data-dir`, ни один к ним не относится. В собранном BB есть `data-testid="plugin-homepage-sections"`, но это не контракт, на него опираться нельзя.
- Замена всей навигации через `experimental_sidebarNavigation` ради одной кнопки отклонена ещё в discovery-home.md.

Что нужно от хоста: либо `experimental_home` из раздела «Пробел хоста» discovery-home.md (тогда перенаправление не нужно вовсе), либо документированный атрибут на кнопке «Домой» и на контейнере экрана нового треда.

## Гарантии задания

| Гарантия | Состояние |
|---|---|
| Прямые ссылки на треды | Не затронуты: на маршруте треда секция не монтируется. |
| Восстановление конкретного треда при старте | Не затронуто по той же причине. Если BB стартует на корневом `/`, сработает перенаправление. |
| Команда нового треда | Работает из Чертога (пропуск) и для экрана с проектом в маршруте. Штатная команда без проекта перенаправляется, см. ограничение 1. |
| История навигации | Перенаправление не добавляет записей и не зацикливает «назад». Вернуться кнопкой «назад» на экран нового треда нельзя, см. ограничение 4. |
| Выключение настройки | Переходов нет. На экране нового треда остаётся секция Чертога: заголовок и кнопка, см. ограничение 6. |
| Выключение плагина | Секция и перенаправление исчезают вместе с плагином, штатный Home возвращается полностью. |

## Ограничения

Каждое воспроизводится при включённой настройке. Все выведены из кода и контракта, в запущенном BB не воспроизводились.

1. **Штатная команда нового треда без проекта.** Открыть тред, вызвать команду нового треда из палитры, сочетанием клавиш или кнопкой в навигации. Если хост ведёт её на корневой `/`, вместо экрана нового треда откроется Чертог. Публично отличить такую команду от случайного Home нельзя: тот же маршрут, те же пропсы секции, чужие команды плагину не видны. Какой именно маршрут открывает штатная команда, не проверено. Обход для пользователя: «Новый тред» в Чертоге или новый тред из проекта.
2. **«Домой» в новой вкладке.** `goHome({ target: "tab" })` открывает экран нового треда во вкладке браузера. Во вкладке без пропуска откроется Чертог.
3. **`toCompose` других плагинов.** Плагин с кнопкой «создать через чат» вызывает `toCompose({ initialPrompt })` без `projectId`. Экран будет перенаправлен. Сохранится ли подставленный текст в черновике нового треда, не проверено.
4. **«Назад» на экран нового треда.** В Чертоге нажать «Новый тред», создать тред, нажать «назад». Запись экрана нового треда открывается уже без пропуска и заменяется Чертогом. Дальше «назад» ведёт на предыдущую запись, цикла нет.
5. **Кнопка «Домой» ведёт не в Чертог.** Штатное `goHome` возвращает на последний маршрут списка тредов. Если это был тред, откроется тред, и перенаправления не будет: тред и должен открываться. Из треда «Домой» ничего не делает. Перенаправление ловит только попадание на корневой экран нового треда.
6. **Секция видна на штатном экране.** Хост рисует у каждой секции заголовок `h2` с её `title`. Когда посещение остаётся на штатном экране (настройка выключена, пропуск, проект, split), под композером видны заголовок и кнопка «открыть Чертог». Убрать их при включённом плагине публично нельзя.
7. **Кадр штатного Home.** Переход выполняется в `useEffect`, после первой отрисовки. Перед Чертогом может мелькнуть штатный экран. Скрыть его нечем (раздел «Что скрывается»).
8. **Пропуск старше 5 секунд.** Если экран нового треда появился позже чем через 5 секунд после действия Чертога, пропуск истёк и экран перенаправится.
9. **Настройки не пришли.** Пока `useSettings().values` не определено, перенаправления нет. Если настройки не загрузятся совсем, остаётся штатный Home.

## Проверено

`npm run check` и `npm run build` в `plugins/chertog` на SDK 0.6.157.

- `tests/core/home/decision.test.ts` — таблица решений: единственная комбинация с переходом, каждая причина остаться, порядок причин.
- `tests/core/home/new-thread-pass.test.ts` — одноразовость, границы срока (0, 5000, 5001 мс), часы назад, недопустимый срок.
- `tests/core/home/presence.test.ts` — один переход на посещение, ожидание настройки, перемонтирование в одном обновлении, десять посещений подряд.
- `tests/adapters/home/controller.test.ts` — поддельная навигация: ровно один `toPluginPanel("home", { replace: true })`, ноль при выключенной и неизвестной настройке, при пропуске, проекте и split.
- `tests/adapters/home/new-thread.test.ts` — пропуск выдаётся до `toCompose`; следующее посещение перенаправляется.
- `tests/adapters/home/facts.test.ts` — чтение фактов.

## Не проверено

- Всё поведение в запущенном BB: переход, `replace` в истории, кадр штатного экрана, вид секции с кнопкой.
- Компонент `HomeRedirectSection` не отрисовывался в тестах: в плагине нет DOM-окружения для тестов (`jsdom`, `happy-dom`), а `package.json` вне этого среза. Тестами покрыты контроллер и чтение фактов, которые компонент вызывает; сама связка хуков проверена только типами.
- Что `useSidebarSplitLayout()` возвращает данные из компонента секции, а не только внутри sidebar. Если там всегда `null`, защита split не действует и экран нового треда в панели split будет перенаправлен.
- Что хост монтирует секцию и вызывает эффекты в порядке, при котором перемонтирование укладывается в одно обновление.
- Какой маршрут открывают штатная команда нового треда и «Новый тред» в навигации.
- Поведение `toPluginPanel` из секции, когда `navPanel` Чертога не зарегистрирована.
- Работа в компактном окне и в веб-клиенте.
