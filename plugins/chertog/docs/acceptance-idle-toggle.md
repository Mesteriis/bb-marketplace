# Приёмка: стоимость покоя и переключатели частей

Веб-прогон 23.11.2026 на изолированных стендах по [e2e-stand.md](e2e-stand.md): BB 0.50.1 (`/Applications/dev/bb.app`), Node 24.20.0, `chrome-headless-shell` 1248, окно 1440×900. Порты стендов выбирались свободные (56024 и 56031); рабочий BB (38886) и тестовый (48886) не затрагивались. На обоих стендах стоят Чертог, Makosh Navigation и Makosh Sidebar (копии `git archive` `plugins/navigation` и `plugins/sidebar` на `HEAD`).

Стенд «после»: Чертог из `git archive` `2ebeff03` (`HEAD` ветки). Стенд «до»: Чертог из `git archive` `7ccd12f8`, коммита перед Task 1 (раздел «Список тредов» строится всегда, `ThreadDirectory.set` не отсекает одинаковое содержимое).

## Вывод

- JS Чертога в покое на странице с открытым тайлом: **1,04 % времени главного потока до, 0,06 % после** (около 210 мс за 20 с против 12 мс), то есть в 18 раз меньше. Это доля только кадров, чей ближайший скрипт из бандла Чертога; работа хоста (React, DOM), которую запускает Чертог, засчитана хосту.
- **Полное время главного потока окна не изменилось**: `TaskDuration` в среднем 0,99 с за 20 с и до, и после (по трём прогонам). `ScriptDuration` упал с 0,33 до 0,11 с (минус 0,22 с, совпадает с падением Чертога), но `RecalcStyleDuration` вырос с 0,12 до 0,24 с. Причина роста не выяснена: трассы не сохранялись, сравнить число и инициаторов `UpdateLayoutTree` нечем. Стенд почти простаивает (около 5 % занятого времени), поэтому разница может быть и шумом. Утверждать, что окно стало дешевле, на этом стенде нельзя.
- Оба переключателя частей работают на настоящем стенде: запись настройки вызывает `onChange` сервера, `makosh-navigation` и `makosh-sidebar` выключаются и включаются штатно (хост ошибок не вернул), на экране появляется штатная навигация и штатный список тредов и возвращаются обратно. «Тайловое пространство» окно читает через `useSettings`.
- «Тайловое пространство» переключено командой, пока одна страница оставалась открытой на `/plugins/chertog/home`: выключено, тайлы исчезли, страница пишет, что пространство выключено, клик по треду в Makosh Sidebar открыл тред штатно (`/threads/thr_other`); включено снова, и при возврате на страницу Чертога (история, без перезагрузки) тайл, созданный в этой странице, снова показывает свой тред, а не «Вернуть панель в это окно».
- Дефектов продукта на стенде не найдено.

## Как менялись настройки

Командой `bb plugin config chertog set <ключ> <true|false>` стенда (CLI с `BB_SERVER_URL` стенда). Интерфейс настроек в браузере не использовался: CLI идёт тем же путём записи настроек на сервере, который вызывает `onChange` плагина. Между записью и проверкой 3 с.

## Профиль покоя (п. 3)

Сид: [acceptance-idle-toggle/seed.mjs](acceptance-idle-toggle/seed.mjs), 41 тред (по 12 родителей с двумя субтредами и пять из [acceptance-open/seed.mjs](acceptance-open/seed.mjs)). Статусы: [churn.mjs](acceptance-idle-toggle/churn.mjs) раз в 1–2 с пишет в базу стенда случайный статус (`idle`, `active`, `error`) трём тредам и затем вызывает `bb thread unread/read` одного из них. Без этого вызова окно изменений не видит: запись прямо в базу не публикуется (за 12 с 0 кадров WebSocket). С ним окно получает 11–14 кадров за 20 с (событие `changed thread read-state-changed`) и перечитывает список. Профиль: [profile.mjs](acceptance-idle-toggle/profile.mjs), CDP `Profiler` с интервалом 250 мкс, 20 с, страница после 4 с покоя. Отнесение выборок: [attribute.mjs](acceptance-idle-toggle/attribute.mjs), ближайший кадр из `plugin-app-assets/<хеш>`; хеш сопоставлен плагину по `bb plugin list --json`.

| Страница Чертога, один открытый тайл (`home-tile`) | 3 | 210 (1,04 %) | 11,6 (0,06 %) |

Разброс по прогонам: `home-tile` до 205/212/212 мс, после 2,8/16,8/15,3 мс. Сырые профили и сводка по прогонам: `$BB_THREAD_STORAGE/idle-toggle-prof/`.

Что считалось: «до» — в основном `e._zod.parse`/`e._zod.check` (разбор схем) и безымянные функции; «после» — `getBoundingClientRect` (измерение тайла).

## Не проверено

- Встроенные тайлы (Telegram, Zoom, SSH/RDP/VNC) после «выключить, включить» в открытом окне: по коду возвращаются карточкой «Повторить» (README), на стенде не запускались.
- В `live-L6` два первых тайла показывают «Вернуть панель в это окно»: их создали окна прежних прогонов, уже закрытые. Это та же карточка, что в `live-L2` до выключения, а не следствие выключения. Поле `handoffCard` в `live-*.json` её не ловит (текст вне тайла), смотреть надо снимки.

- Окно выбора открыто (`picker`): сценарий `home-picker` из-за сохранённой раскладки шёл с одним открытым тайлом, без окна выбора. Построение разделов при открытом окне выбора не профилировалось; по Task 1 оно должно остаться таким же, как «до».
- Реальные запущенные агенты: статусы подделаны записью в базу, а не работой агентов, поэтому число событий и размер списка (41 тред) меньше, чем у рабочей установки; проценты рабочего BB здесь не воспроизведены.
- Тихий старт: стенд не перезапускался с выключенным `navigationPart`; «ничего не делать на старте» (R3) на стенде не проверялось, только модульными тестами.
- Интерфейс настроек BB в браузере.
- Нативные окна Desktop; стенд веб.

## Особенности стенда

- Установка плагина просит у сервера собрать набор сборки (`npm install esbuild …`), для этого нужен доступ к `registry.npmjs.org`. В песочнице агента без доступа установка висит; второй стенд получил готовый каталог `data/plugins/toolchain-*` от первого.
- `chrome-headless-shell` из песочницы агента не запускается (`bootstrap_check_in … Permission denied`); браузерные команды шли без песочницы, но только к портам стенда.
- Пакет `better-sqlite3` (devDependency навигации) в песочнице не собирается; для `navigation` и `sidebar` использован `npm ci --ignore-scripts` (на работу плагинов это не влияет: оба собрались и запустились).
