# Чертог: поверхности провайдеров

Отчёт по разделу 2 п. 2 и разделу 3 «Поставщики» задания `plugins/chertog/docs/spec.md`.
Это чтение кода, а не прогон: ни один провайдер не запускался, ни один файл провайдера не менялся.

## 0. Область и способ проверки

| Что | Значение |
|---|---|
| Checkout | worktree `bb-main`, `HEAD` `ccad3f57` (21.11.2026), `main` `3ed0189a` |
| Контракт SDK | установленные типы `@get-bb/plugin-sdk` **0.6.132** (`bundled-types/bb-plugin-sdk-app.d.ts` в основном checkout; в этом worktree `node_modules` нет) |
| Срез upstream из задания | SDK 0.6.178, Desktop 0.50.1. Расхождение с 0.6.132 по затронутым API ниже помечено |
| Исходники хоста BB (`apps/app`, `apps/desktop`) | в checkout отсутствуют: всё о поведении хоста — не проверено |
| Запускаемая сборка BB | не проверено |

Слова в таблицах: **да** — видно в коде и доступно публичным API; **частично** — работает с оговоркой из колонки ограничений; **нет** — по коду невозможно; **не проверено** — нужен запуск или недоступный исходник.

Всё, что касается поведения при `1 → 2 → 1`, переключении вкладки BB, reload и закрытии окна, по каждому провайдеру **не проверено**: это свойства хоста, которые из кода плагина не выводятся. Ниже описано только то, что плагин делает при размонтировании и повторном монтировании своего компонента.

## 1. Что публичный API даёт стороннему плагину (общее для всех)

Проверено по типам SDK 0.6.132.

| Операция | Что она делает | Для Чертога |
|---|---|---|
| `useBbNavigate().toPluginPanel(path, { subPath })` | Переход на nav-панель **своего** плагина | Чужой маршрут ею открыть нельзя |
| `experimental_useSidebarNavigation().actions.activate(itemId, { target })` | Открывает любой пункт навигации на месте, в split или во вкладке; у предела панелей заменяет сфокусированную | Работает только внутри слота `experimental_sidebarNavigation`: вне sidebar возвращает пустой список и действия-пустышки. Замена панели у предела противоречит требованию задания не вытеснять живую панель |
| `experimental_useAppPanel().openTab({ tab, params })` | Открывает вкладку правой панели | Ссылка на вкладку привязана к владельцу: чужую вкладку так не открыть (не проверено запуском) |
| `ThreadChat` (`threadId`, `variant`, `layout="contained"`) | Чат существующего треда внутри слота плагина | Единственный чужой «экземпляр», который встраивается штатно |
| `experimental_appOverlay` | Один компонент на окно, живёт дольше страницы | Кандидат на собственный стабильный host. Чужую панель не монтирует |
| `useSidebarSplitLayout()` | Проекция split: `paneId`, прямоугольник, `threadId` или `null` | Только чтение; тип и параметры страницы плагина не видны |
| `useBbNavigate().openUrl(url)` | Открывает URL по настройке браузера BB | Не возвращает ID вкладки или view |
| `useBbNavigate().experimental_openFilePreview({ opener })` | Открывает файл в общей панели предпросмотра | `opener` — только свой `fileOpener` |

Вывод: публичного способа смонтировать компонент чужого плагина в своём контейнере нет. `experimental_useActiveComposer` в типах 0.6.132 не найден (в задании он относится к 0.6.178).

## 3. Telegram — `plugins/telegram`

- **Поставщик и версия.** `bb-plugin-makosh-telegram` 0.1.0, SDK 0.6.132, свой пакет Makosh.
- **Регистрация.** `navPanel` `telegram` с `experimental_sidebar` (`plugins/telegram/app.tsx:2363`); фиксированная вкладка `chat-details` в контексте этой панели (`plugins/telegram/app.tsx:2373`); два `pendingInteraction` для подтверждений агента.
- **Создание и cleanup.** `TelegramPanel` (`plugins/telegram/app.tsx:133`), размонтирование React. Список чатов и детали рисуются порталом в слоты sidebar и правой панели через два модульных outlet (`plugins/telegram/src/adapters/bb/workspace-panels.tsx`).
- **ID сессии и представления.** Сессия — аккаунт TDLib на сервере плагина; активный аккаунт выбирается RPC и общий для всех окон. У представления своего ID нет. Открытый чат — `useState` страницы (`plugins/telegram/src/ui/telegram-page.tsx:552`).
- **Операция открытия экземпляра.** Только маршрут панели; `subPath` знает одно значение `settings`. Адреса чата нет.
- **Backend.** Обычный DOM в документе BB. Mini App и Instant View используют iframe (`plugins/telegram/src/ui/mini-app.tsx`, `plugins/telegram/src/ui/instant-view.tsx`); видео звонка (`plugins/telegram/src/ui/private-call-video.tsx`) — не проверено.
- **Смена страницы и размонтирование.** Автор сам ожидает remount при изменении split (`plugins/telegram/app.tsx:129`). Черновики лежат в модульной карте по аккаунту (`plugins/telegram/app.tsx:130`, не больше 16 аккаунтов) и переживают remount в пределах окна; после reload — нет. Последний чат пишется в `localStorage` под ключом аккаунта (`plugins/telegram/src/ui/conversation-location.ts`). Caret, выделение и позиция чтения после remount — не проверено.
- **Ограничения.** Один «текущий чат» на аккаунт: ключ в `localStorage` один, outlet-ы единственные на окно. Два экземпляра страницы в одном окне будут спорить за outlet и за последний чат. Это ровно случай задания «не эмулируй multi-instance переключением глобального адресата».
- **Минимальный адаптер или пробел.** На стороне Telegram: `subPath` вида «чат такого-то аккаунта» и ключ места разговора на экземпляр, а не на аккаунт. На стороне хоста: пробел H1 (раздел 12). До этого Чертог может только показать штатный маршрут в одной панели.

## 4. Zoom — `plugins/zoom`

- **Поставщик и версия.** `bb-plugin-makosh-zoom` 0.1.0, SDK 0.6.132, свой пакет Makosh.
- **Регистрация.** Один `navPanel` `zoom` (`plugins/zoom/app.tsx:46`).
- **Создание и cleanup.** Звонок — состояние `active` экрана календаря (`plugins/zoom/src/ui/calendar-screen.tsx:39`), пока оно задано, вместо календаря рисуется `CallPanel` (`plugins/zoom/src/ui/calendar-screen.tsx:119`). Cleanup панели снимает только таймер и обработчик сообщений (`plugins/zoom/src/ui/call-panel.tsx:128`); команды «выйти» при размонтировании нет, звонок обрывается вместе с iframe.
- **ID сессии и представления.** Нет ни того, ни другого. Есть номер встречи внутри подготовленного звонка; сервер звонок не ведёт (одноразовые билеты нужны только для переноса в системный браузер, `plugins/zoom/src/adapters/bb/call-tickets.ts`).
- **Операция открытия экземпляра.** Только маршрут панели. Войти во встречу по адресу нельзя: `subPath` не читается.
- **Backend.** iframe внутри документа BB (`plugins/zoom/src/ui/call-panel.tsx:193`), страница звонка отдаётся HTTP-маршрутом плагина с другого loopback-имени (`plugins/zoom/src/core/redirect.ts:30`), в ней Zoom Meeting SDK, embedded-клиент (`plugins/zoom/src/adapters/bb/call-page.ts:121`). Это не desktop native view: правила браузерного backend из раздела 1 задания на него не распространяются. Демонстрация экрана внутри BB не работает; есть уход в системный браузер (`plugins/zoom/src/adapters/bb/open-in-browser.ts`).
- **Смена страницы и размонтирование.** По коду: уход со страницы Zoom размонтирует `ZoomPanel`, iframe уничтожается, участие и медиа теряются. Запуском не проверено.
- **Ограничения.** Один звонок на экземпляр страницы; runtime встречи неотделим от iframe. Повторный вход — второе участие, плагин сам закрывает встроенный звонок перед уходом в браузер, чтобы не занять два места (`plugins/zoom/src/ui/calendar-screen.tsx:88`).
- **Минимальный адаптер или пробел.** Нужен адаптер поставщика: держать iframe звонка в компоненте `experimental_appOverlay` самого Zoom (время жизни окна, как у Terminals) и только позиционировать его по прямоугольнику, который сообщает страница или Чертог. Без этого перенос звонка в соседний тайл невозможен. Перед закрытием последнего вида Чертог обязан предупреждать: закрытие завершает участие.

## 5. Remote Hub — `plugins/remote-hub`

- **Поставщик и версия.** `bb-plugin-makosh-remote-hub` 0.1.0, SDK 0.6.132, свой пакет Makosh, Rust-helper.
- **Регистрация.** `navPanel` `remote-hub-ssh`, путь `ssh`, со своим sidebar (`plugins/remote-hub/app.tsx:284`); вкладка треда `remote-session-live` с параметром `sessionId` (`plugins/remote-hub/app.tsx:276`, `plugins/remote-hub/src/ui/reveal.ts:15`); директива сообщения `remote-session`; `experimental_appOverlay` с баннером агента; сегмент контекста треда.
- **Создание и cleanup.** Сессиями владеет helper через сервис (`plugins/remote-hub/src/adapters/bb/service.ts`); отсоединение вида сессию не завершает. Вид SSH при размонтировании шлёт `detach`, закрывает сокет и уничтожает xterm (`plugins/remote-hub/src/ui/ssh-terminal.tsx:207`).
- **ID сессии и представления.** Сессия: `generation` (32 hex, поколение helper) плюс `sessionId`, вместе «ключ сессии». Запись на «столе» имеет свой локальный `id`, который переживает reconnect (`plugins/remote-hub/src/core/desk.ts:16`). Вид RDP получает `viewId` при attach (`plugins/remote-hub/src/adapters/bb/service.ts:1093`).
- **Операция открытия экземпляра.** Маршрут панели с ключом сессии в `subPath` (`plugins/remote-hub/app.tsx:188`); вкладка треда через `openTab` с `params`. Обе вызываются из самого плагина; из чужого плагина доступен только URL маршрута. Attach идёт по RPC плагина и чужому плагину недоступен.
- **Backend.** SSH и терминал PVE — xterm.js поверх бинарного WebSocket с attach-токеном; RDP — canvas (`plugins/remote-hub/src/ui/rdp-canvas.tsx`); графика VM — noVNC (`plugins/remote-hub/src/ui/vnc-view.tsx`). Всё в DOM документа BB.
- **Смена страницы и размонтирование.** SSH и RDP: вид уничтожается, сессия и PTY остаются у helper, новый вид получает ограниченный снимок scrollback (`plugins/remote-hub/src/ui/ssh-terminal.tsx:136`). Тот же PTY и процесс при переносе — ожидаемо по коду, запуском не проверено; scrollback сверх снимка и выделение текста теряются. Графика VM: вид ровно один за всю жизнь консоли, его уход закрывает консоль (`plugins/remote-hub/src/adapters/bb/service.ts:1213`, `plugins/remote-hub/src/ui/live-session.tsx:52`).
- **Ограничения.** Право ввода не следует за фокусом: аренда управления и «Take control» остаются у Remote Hub (`plugins/remote-hub/src/core/control-lease.ts`). Агент действует, только пока живой вид сессии виден в сфокусированном окне, поэтому скрытие тайла Чертогом меняет доступ агента. После перезапуска вкладки возвращаются в состоянии `not_connected`; ключ сессии с прежним `generation` недействителен.
- **Минимальный адаптер или пробел.** Для SSH и RDP достаточно показать штатный маршрут с ключом сессии: перепривязка уже есть. Сохранять в раскладке нужно цель (профиль или гость PVE), а не ключ сессии. Графику VM нельзя переносить remount-ом вовсе: нужен либо пробел H1, либо запрет переноса с объяснением в меню.

## 6. Terminals — `plugins/terminals`

- **Поставщик и версия.** `@gpambrozio/bb-plugin-terminals` 0.4.0, SDK 0.6.104, импортированный subtree (`plugins/terminals/LOCAL_FORK.md`).
- **Регистрация.** `navPanel` `terminals` и два `experimental_appOverlay`: `lifetime` и `chat-delivery` (`plugins/terminals/app.tsx:26`).
- **Создание и cleanup.** Терминалы живут в модульном реестре по `terminalId` всё время окна, а не страницы (`plugins/terminals/app/live-terminals.ts:214`). Страница перевешивает тот же DOM-элемент (`plugins/terminals/app/live-terminals.ts:166`). Реестр очищается, когда overlay `lifetime` размонтируется при выгрузке плагина (`plugins/terminals/app.tsx:21`, `plugins/terminals/app/live-terminals.ts:237`).
- **ID сессии и представления.** `terminalId` — это ID терминальной сессии BB (`bb.sdk.terminals`) и одновременно ID вкладки (`plugins/terminals/shared/tabs.ts`). Отдельного ID представления нет: один xterm на `terminalId` на окно.
- **Операция открытия экземпляра.** Только маршрут страницы. Выбранная вкладка — состояние окна в модуле и `localStorage` (`plugins/terminals/app/selection.ts:7`); `subPath` не читается.
- **Backend.** xterm.js в DOM, WebSocket к терминалу BB; shell и PTY ведёт host-демон машины (`plugins/terminals/server/service.ts:5`).
- **Смена страницы и размонтирование.** Уход со страницы оставляет xterm, scrollback и сокет; возврат показывает тот же элемент на той же строке. После reload карта пуста, вкладка подключается заново и BB отдаёт последние 512 КБ вывода (`plugins/terminals/app/connection.ts`).
- **Ограничения.** Закрытие вкладки завершает shell (`plugins/terminals/server/service.ts:175`): для Чертога это «выйти из сессии», а не «убрать из раскладки». Список вкладок общий для всех окон, размер shell задаёт окно, которое сейчас в работе (`plugins/terminals/app/sizing.ts`); два одновременных вида одного терминала в разных окнах — не проверено.
- **Минимальный адаптер или пробел.** Готовый образец стабильного host в одном документе. Для Чертога не хватает адреса вкладки: `subPath` с `terminalId`. Собственный вид Чертога через `useSdk().terminals` технически возможен, но это второе представление той же сессии; допустимость и поведение размера — не проверено. Терминал треда самого BB и неслитый PR #7801 — не проверено, исходников нет.

## 7. Markdown Editor — `plugins/markdown-editor`

- **Поставщик и версия.** `bb-plugin-markdown-editor` 0.2.1, SDK 0.4.84, импортированный subtree (`plugins/markdown-editor/LOCAL_FORK.md`).
- **Регистрация.** `fileOpener` `markdown-editor` для редактируемых расширений (`plugins/markdown-editor/app.tsx:369`) и content script с карандашом в заголовке diff (`plugins/markdown-editor/app.tsx:381`).
- **Создание и cleanup.** Хост рисует `MarkdownEditorTab` как вкладку файла (`plugins/markdown-editor/app.tsx:62`); cleanup — размонтирование React.
- **ID сессии и представления.** Сессии нет. Экземпляр задают `path` и `source` файла, которые передаёт хост; ID вкладки принадлежит хосту.
- **Операция открытия экземпляра.** Чужой плагин может открыть файл в общей панели предпросмотра, но выбрать именно этот редактор не может: применится выбор пользователя в «Настройки → Файлы».
- **Backend.** DOM: textarea и предпросмотр. Чтение и запись по RPC с проверкой `sha256`.
- **Смена страницы и размонтирование.** Буфер лежит в `useReducer` компонента: при размонтировании несохранённый текст теряется. Защита есть только от выгрузки окна (`plugins/markdown-editor/app.tsx:170`).
- **Ограничения.** Редактор существует только как вкладка боковой панели, не как страница или центральная панель.
- **Минимальный адаптер или пробел.** Штатно — открыть файл в панели рядом с тредом. Тайл-редактор в рабочем поле требует пробела H1 или собственного редактора Чертога, что задание запрещает как второй движок только для доменных сессий; для файла это допустимо, но несохранённый буфер чужого редактора перенести нельзя.

- **Операция открытия экземпляра.** Маршрут страницы с адресом ревью в `subPath` (`plugins/diff-review/app/reviews-page.tsx:59`); CLI `bb diff-review open` рассылает запрос окнам, и окно с этим тредом открывает ревью (`plugins/diff-review/app/open-overlay.tsx`). Вызов команды `open` из чужого плагина — не проверено.
- **Backend.** DOM. Диффы читает host-entry, комментарии хранит сервер плагина.
- **Смена страницы и размонтирование.** Место прокрутки запоминается как файл и смещение в нём (`plugins/diff-review/app/scroll-memory.ts`). Незаконченный комментарий после remount — не проверено.
- **Ограничения.** Вкладка `review` существует только у существующего треда.
- **Минимальный адаптер или пробел.** Наиболее готовый провайдер: в раскладке хранится `threadId` и цель, показ — штатным маршрутом страницы. Встраивание в тайл — пробел H1.

## 9. App Preview — `plugins/app-preview`

- **Поставщик и версия.** `bb-plugin-app-preview` 0.2.9, SDK 0.4.34, импортированный subtree (`plugins/app-preview/LOCAL_FORK.md`).
- **Регистрация.** `threadPanelAction` `preview`, кнопка в заголовке треда, действие палитры `open-preview`, `navPanel` `ports`, `pendingInteraction` подтверждения (`plugins/app-preview/app.tsx:495`).
- **Создание и cleanup.** `PreviewPanel` получает `threadId` (`plugins/app-preview/app.tsx:155`). Процесс приложения запускает и держит сервер плагина (`plugins/app-preview/service.ts`), панель его не владеет.
- **ID сессии и представления.** Предпросмотр привязан к `threadId`. Сервер записывает вкладку браузера в список вкладок треда и хранит её `tabId` (`plugins/app-preview/browser-tabs.ts:79`).
- **Операция открытия экземпляра.** Панель треда открывается действием палитры; само приложение — через `openUrl` (`plugins/app-preview/app.tsx:212`).
- **Backend.** Плагин не рисует приложение сам: ни iframe, ни своего view. Страницу показывает браузер BB. Что это на Desktop (native view или иное) и кто владелец — не проверено, это код хоста.
- **Смена страницы и размонтирование.** Процесс предпросмотра переживает размонтирование панели. Судьба вкладки браузера — не проверено.
- **Ограничения.** Панель и вкладка браузера существуют только в контексте треда.
- **Минимальный адаптер или пробел.** Для iframe-панели этапа A провайдер не нужен: Чертог может показать в своём iframe URL, который вернул сервер предпросмотра, но получить этот URL чужой плагин может только из списка вкладок треда; публичность этого списка для Чертога — не проверено. Удержание native view от выгрузки — пробел H2.

## 10. Bundled Side Chat и Conductor

Каталогов «plugins/side-chat» и «plugins/conductor» в этом checkout нет: оба плагина входят в поставку BB, их исходники здесь недоступны. Регистрация, файлы создания и cleanup, ID, поведение при смене страницы — **не проверено**.

Проверено только по типам SDK 0.6.132: компонент `ThreadChat` экспортируется, принимает явный `threadId`, `variant` (`full`, `compact`, `timeline`) и `layout` (`contained` по умолчанию). Этого достаточно, чтобы на этапе A проверить два существующих треда в собственном контейнере, как требует задание. Маршрутизация команд к composer такого чата на 0.6.132 — не проверено.

## 11. Сводка ограничений

| Провайдер | Главное ограничение | Что делать Чертогу сейчас |
|---|---|---|
| Telegram | Один текущий чат на аккаунт, адреса чата нет | Одна панель со штатным маршрутом; два чата не обещать |
| Zoom | Звонок умирает с iframe страницы | До адаптера не переносить; предупреждать перед закрытием |
| Remote Hub SSH и RDP | Вид пересоздаётся, сессия остаётся | Штатный маршрут с ключом сессии; хранить цель, не ключ |
| Remote Hub VNC | Один вид на всю жизнь консоли | Перенос запрещён, объяснение в меню |
| Terminals | Нет адреса вкладки; закрытие вкладки завершает shell | Штатный маршрут; «убрать из раскладки» не вызывает close |
| Markdown Editor | Только вкладка панели; буфер не переживает remount | Открывать файл штатно рядом с тредом |
| Diff Review | Только вкладка треда или страница | Штатный маршрут с адресом ревью |
| App Preview | Вид принадлежит браузеру BB | Этап A — собственная iframe-панель |

## 12. Пробелы хоста и SDK (узкие предложения, не приватные импорты)

- **H1. Смонтировать панель другого плагина в прямоугольник.** Сейчас чужой `navPanel` или вкладку нельзя показать внутри своего контейнера. Ожидаемая семантика: хост по `pluginId`, `panelId` и `subPath` монтирует компонент владельца в его собственном plugin scope в узел, который дал вызывающий; владелец остаётся прежним, по умолчанию ничего не меняется. Тест: boot ID подконтрольной панели не меняется при смене прямоугольника.
- **H2. Отзывное удержание native view от выгрузки**, привязанное к экземпляру и поколению, без права ввода и чтения страницы. Нужен только если предпросмотр показывается native view; сначала установить фактический backend на Desktop.
- **H3. Открыть чужой маршрут вне sidebar.** `activate` работает только в слоте навигации и у предела панелей заменяет сфокусированную. Нужна операция «открыть маршрут плагина с `subPath`» с отказом вместо замены.
- **Адаптеры поставщиков** (правки не в Чертоге, отдельными задачами): адрес чата в Telegram, overlay-host звонка в Zoom, адрес вкладки в Terminals.

## 13. Что осталось не проверено

- Любое поведение в запущенном BB: `1 → 2 → 1`, переключение вкладки, reload, закрытие окна, компактный экран.
- Фактический backend браузера BB на Desktop и владелец его view.
- Исходники и поведение bundled Side Chat и Conductor.
- Версия SDK и Desktop в реально запускаемой сборке; отличия 0.6.132 от 0.6.178 сверх названных.
- Telegram: caret, выделение и позиция чтения после remount; видео звонка.
- Remote Hub: тот же PTY и процесс после переноса на живом SSH; RDP без reconnect.
- Terminals: два вида одного терминала в двух окнах.
- Вызов команд и вкладок чужого плагина из Чертога.
