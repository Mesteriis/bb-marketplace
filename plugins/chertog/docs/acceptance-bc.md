Веб-прогон 22.11.2026 на локальной ветке `chertog`, SHA `55e16830d40c668c7605e5cb152ae4f556c7fec1`. Итоговая сверка с `b34669c6b99e48986d15c36b684de61eb5d8379b` показала одно изменение — HTML-пробу. Последние изменения пакетов в этой сборке — Чертог `00729f6e`, Telegram `aee537e6`, Zoom `5bd59abc`, Remote Hub `48a040ec`. Критерии — [раздел 5 задания](spec.md). ## Воспроизведение и фиксация результата

Подготовить [изолированный веб-стенд](e2e-stand.md), включить `acceptanceFixture`, добавить Terminals, тестовую среду с `sample.md` в двух ревизиях и тестовый тред с терминалом. Точные имена целей и аргументы запуска заданы в [сквозной пробе B](../tests/adapters/app/stage-b-probe.mjs). Из каталога плагина:

```sh
npm run check
npm run build
node tests/adapters/app/stage-b-probe.mjs "$STAND_URL" "$PLAYWRIGHT_TOOLS_DIR" "$CHROMIUM"
```

Итоги команд, число пропусков и журналы приведены в [протоколе проверки](acceptance-bc/gates.json). Для UI использованы отдельные пустые профили BB и Chromium, `acceptanceFixture=true` и размер 1280×800. В [журнале браузера](acceptance-bc/browser.txt) строки сгруппированы по прогонам. После успешных маршрутов проверено прекращение ответа на /health.

Штатный `npm run check` Telegram последовательно с `VITEST_MAX_WORKERS=1` прошёл с тайм-аутом 5 с, код 0, 1829 тестов прошли, 4 пропущены. Дополнительный последовательный `npx --no-install vitest run --configLoader runner --testTimeout 20000` также завершился с кодом 0, 1829 прошли, 4 пропущены. [Штатный прогон](acceptance-bc/telegram-check-serial.txt), [прогон с 20 с](acceptance-bc/telegram-20s.txt). Две предыдущие попытки завершились с кодом 1, во всех перечисленных случаях Vitest сообщил о превышении 5000 мс. В [протоколе команд](acceptance-bc/gates.json) сохранены полные имена параметризованных случаев.

| Запуск с лимитом 5 с | Тесты, превысившие лимит |
|---|---|
| Одновременные проверки четырёх пакетов, 7 тестов | Форма отправки при смене аккаунта с topic undefined. Обложки HDR SMPTE 2084 и ARIB STD-B67. Dolby Vision 8.4. Параметры панели Fixture.default и Archive. Открытие темы форума с подгрузкой истории и возвратом в группу. |
| Telegram с двумя воркерами, 4 теста | Те же две обложки HDR. Dolby Vision 8.1. Сохранение вложений inbox при обновлении деталей чата и пересылке выбранного альбома. |
| Telegram с одним воркером, 0 тестов | Все четыре файла, ранее содержавшие падения, прошли вместе с остальным набором. |

Для повтора маршрутов A, Telegram и выбора провайдеров передать каждой пробе URL изолированного сервера, каталог с playwright-core и путь к Chromium, как в команде выше. Для Telegram установить оба плагина на стенд и применить [патч измерения](acceptance-bc/telegram-immediate.patch) к временной копии браузерной пробы. Для проверки закрытия создать в базе стенда два idle-треда `thr_handoff` («Передача окна») и `thr_neighbor` («Соседний тред»), передать пробе четвёртым аргументом путь к bb.db стенда. Для проверки HTML зарегистрировать среду с [preview.html](../tests/adapters/app/preview.html) и передать путь к тестовому файлу четвёртым аргументом. Для постановки SSH/RDP/VNC и Zoom установить оба провайдера из проверяемой ревизии. Проба владельцев подменяет ответы RPC и сокеты только внутри Chromium стенда. В Zoom проверены выбор приглашения, явный вход и один обмен join/joined с контролируемой страницей в iframe. Устройства захвата не запрашивались. Для проверки участия и медиапотоков нужен отдельный прогон с тестовой встречей и наблюдателем.

Отдельная проба Remote Hub `tests/embed-browser/probe.mjs` на этой сборке завершилась с кодом 1. В её упрощённом runtime отсутствует модуль zod, первый выбор VNC не появился. Для воспроизведения собрать Remote Hub, передать пути к Playwright и Chromium через `PLAYWRIGHT_CORE` и `CHROME`, запустить `node tests/embed-browser/probe.mjs`. Результаты выбора и готовности в таблице получены в установленном BB со штатным runtime.

Для проверки сохранённого протокола выполнить из корня checkout `node plugins/chertog/docs/acceptance-bc/verify.mjs`. Полные необработанные stdout/stderr и отдельные коды выхода сохранены в каталоге артефактов треда `acceptance-bc-raw/`. В Git включены выдержки и SHA-256 полных журналов проверочных команд.

Для каждого повторного прогона записать SHA, версии BB и провайдера, тип стенда, действие, сравнимые обезличенные ID и счётчики до/после, результат команды и первый несовпавший шаг. Для Zoom записать наблюдения второго клиента. Для экранов — масштаб и фактическую рабочую область. Приглашения, переписку и содержимое реальных терминалов в журнал не включать.

| Операция | Что должен предоставить хост |
|---|---|
| Перенести окно и вернуть его при потере экрана | Выбор дисплея по жесту, workArea в DIP, scaleFactor и ограничение фактических bounds вызывающего окна. Обработка исчезновения дисплея должна работать в открытом процессе. [Контракт экранов](stage-c-windows.md). |

| Предоставить защищённый контекст встраивания | Хост связывает контейнер с проверенной идентичностью владельца, экземпляром и поколением, отзывает доступ при освобождении. Владелец проверяет права ресурса и обрабатывает ввод. [Модель доверия](provider-embed.md), [текущий договор обмена](embed-wire-v1.md). |
