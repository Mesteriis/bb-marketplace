# Границы доступа Commander

BB 0.50.1 помечает UI и команды владельца как `experimental_caller.kind = "client"`. Тот же тип получает агент с доступом к shell и клиенту BB. Прямой запуск CLI имеет права клиента владельца. Модель с ограниченными правами действует через `commander_*`. Вызовы входящего RPC от других плагинов получают `forbidden`.

Грант связывает тред, endpoint, область путей и разрешения. Звёздочка в идентификаторе треда включает все треды, звёздочка в endpoint включает все endpoints. Сравнение областей учитывает регистр. Запуск сверяет владельца плана и digest, затем читает актуальные гранты. Автоматическая запись требует охвата каталога назначения, поскольку временный файл и имя после разрешения конфликта могут быть соседями первоначальной цели. Перенос с удалением источника, удаление и выход за грант требуют одобрения владельца. Перед одобрением Commander сверяет источники и назначения с планом. Изменение гранта применяется к следующим запросам.

Удалённый доступ дополнительно контролирует Remote Hub. Commander не читает хранилище учётных данных, не получает пароли и ключи SSH. SFTP не гарантирует отсутствие перехода по промежуточному симлинку. Автоматический агентский доступ к SFTP требует гранта на корень удалённого endpoint для соответствующей операции. Для более узкого SFTP-гранта прямой просмотр закрыт, а запись требует одобрения. Локальный адаптер проверяет промежуточные компоненты и дескрипторы. Внешний процесс может изменить родительский каталог в промежутке между проверкой и системным вызовом.

Агентам доступны метаданные в области гранта, идентификаторы планов и состояние собственных задач. Цель симлинка и подробный план в агентский ответ не входят. Успех подготовки плана может подтвердить, что запрошенная операция технически возможна. Содержимое файлов агентские инструменты не возвращают. В realtime публикуются только идентификаторы. Повреждённые задачи видны как диагностические записи с идентификатором и состоянием.

Планы до запуска хранятся в памяти до 30 минут. Запущенные задачи и контрольные точки хранятся в SQLite. При выгрузке плагина активные шаги прерываются. Следующий запуск сверяет контрольные точки, прежде чем продолжить задачу. Неоднозначный исход требует проверки владельцем.
