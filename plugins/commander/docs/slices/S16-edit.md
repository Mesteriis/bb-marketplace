# S16 — F4 по серверу

F4 всегда вызывает собственный `slots.fileOpener` с `extensions: []` через
`experimental_openFilePreview({ target: { kind: "host", hostId, path }, location: null, opener })`
с явным ID. Если редактор недоступен, Commander сообщает об этом и показывает
путь к копии. Копия создаётся host entry в выделенном каталоге под
`experimental_paths.dataDir`; редактор сохраняет её через RPC Commander.
Сервер связывает копию с сессией владельца и хостом; UI не передаёт путь для
чтения, записи или удаления. F4 доступен только RPC клиента-владельца.

Открытие принимает обычный UTF‑8 файл в пределах бюджета `readForView`.
Для провайдеров с SHA‑256 база включает размер, mtime и SHA‑256 исходных
байтов. Перед постановкой записи сверяются все три поля. Содержимое копии
проверяется по SHA‑256 при переносе через штатную очередь.

Для SFTP без `provider.sha256` база и `expectTarget` содержат размер и mtime.
Открытие показывает объём чтения и запрашивает подтверждение владельца.
Выбранная проверка совместима с условиями штатной очереди и SFTP-адаптера
при смене файла. Повторная загрузка под `estimateId` дала бы более сильную
проверку перед запуском, но текущий SFTP-адаптер всё равно сверяет только
метаданные непосредственно перед заменой. Остаточный риск — правка того же
размера с тем же серверным mtime, в том числе в пределах одного тика часов
сервера, может остаться незамеченной. Дополнительно сохраняется окно между
финальной проверкой и удалённым rename.

Кнопка «Записать обратно» проверяет оригинал. Изменение или удаление
возвращает конфликт. «Перезаписать» сверяет состояние повторно с показанной
версией. «Сохранить рядом» создаёт `name (edited).ext` через штатный план
копирования с `expectTarget: "absent"`. «Сравнить» читает текущую версию
через просмотр S15. Очередь выполняет перенос через временный файл и
rename. Закрытие сессии удаляет копию; занятые очередью копии сохраняются до
завершения использующего их задания. При запуске чистятся осиротевшие копии.
