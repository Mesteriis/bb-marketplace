# ADR 0002 — Ввод-вывод Commander на этапе 2a

Статус: **accepted**, 2026-11-27 — принят координатором thr_mn6uyba78h по ревью astra+opus.

Основание — [дизайн этапа 2](../stage-2-design.md), [ADR 0001](0001-foundation.md) и [аудит S9](../../research/stage-2-libs.md).

## Архивы

Предлагается отдельный Rust-процесс с `zip` 8.6.0 (MIT, возможности
`deflate` и `aes-crypto`) и `tar` 0.4.46 (MIT OR Apache-2.0, без
`xattr`). Чтение и упаковка используют потоки. ZIP требует произвольного
доступа к центральному каталогу. Для SFTP адаптер сначала переносит архив
в ограниченную по размеру локальную копию через штатное чтение Remote Hub.
Статус переноса и отмена видны в задании. Проксированный `Read + Seek`
от FileProvider по stdio не проверен. TAR можно читать последовательно.
Извлечённые записи идут через FileProvider и JobRunner с проверкой цели.

- **ZIP, чтение.** ZIP64, UTF-8 и CP437, с сохранением исходного имени в
  байтах там, где библиотека его предоставляет. Для других кодировок проверять
  возможность явного декодирования сырых имён и коллизии после декодирования.
  Чтение ZipCrypto и WinZip AES разрешать только с введённым паролем. Ошибка
  проверки целостности, неверный пароль или прерванный поток оставляют только
  временный результат, который удаляется.
- **ZIP, запись.** Обычный ZIP или WinZip AES по запросу. Новые архивы с
  ZipCrypto оставляем за рамками рекомендации. Публичный способ записи
  ZipCrypto в `zip` находится в `unstable`, сам алгоритм устарел.
- **Изменение ZIP/TAR.** После реализации проверок перезаписывать архив в
  соседний временный файл, перечитывать результат и проверять fingerprint
  оригинала перед заменой. При конфликте сохранять оригинал. Для ZIP
  отдельно проверить, что повторная упаковка сохраняет нужные метаданные и
  исходные имена. До такой проверки неподдерживаемые варианты явно отклонять.
- **TAR.** Чтение и запись USTAR/PAX потоком. Сохранять имена как байты в
  адаптере, повторное кодирование — по проверяемым правилам назначения.
  Шифрование не является частью формата TAR.
- **7z/RAR.** Оба остаются предметом аудита.

Адаптер проверяет полные имена и типы записей, повторы и коллизии,
относительность путей, ссылки и специальные файлы до передачи записи на
запись. Он ограничивает фактически обработанные байты, число записей,
коэффициент сжатия и место, занятое временными файлами. Настройки по
умолчанию — 10 ГиБ распакованного, 100 000 записей и отношение
распакованного размера к сжатому не более 100:1.

- **TAR до буферизации.** `tar` 0.4.46 читает GNU longname/longlink и
  локальный PAX целиком в `Vec`. Перед обычной итерацией свой ограниченный
  разбор 512-байтовых заголовков проверяет checksum, тип и размер с
  проверяемой арифметикой для octal/base-256 и выравнивания. Для `L`, `K`,
  `x`, `g` проверять размер до чтения тела. Предлагаемый лимит 1 МиБ на
  служебную запись и 4 МиБ накопленных метаданных архива. Служебные записи
  входят в общий счётчик. Сканер либо учитывает PAX `size` при вычислении
  смещения следующего заголовка, либо явно отклоняет переопределение и
  другие неподдерживаемые форматы, включая sparse. Обычные тела пропускаются
  с фиксированным буфером или через seek. Проверка и парсинг используют один
  открытый приватный файл, для чтения по сети допустима ограниченная
  локальная копия. Ограничение общего потока само по себе не ограничивает
  память, выделяемую на одну служебную запись.
- **ZIP до построения индекса.** Своим разбором проверить EOCD в ограниченном
  хвосте файла, включая размер комментария, и при нужных маркерах — ZIP64
  locator и ZIP64 EOCD по проверенным смещениям. Отклонить многотомность,
  усечение, смещения или размеры вне файла и переполнение арифметики.
  До `ZipArchive::new` проверить число записей (100 000 по умолчанию) и
  размер центрального каталога (64 МиБ по предложению S9). Пройти каталог
  ограниченными чтениями для проверки фактического количества записей,
  границ и повторяющихся имён, которые библиотека может скрыть в индексе.
  `enclosed_name()` — вторая линия после проверки сырых и нормализованных
  путей адаптером. Решения по symlink и другим типам записей остаются в адаптере.

Проверки бомб, traversal и выходящих ссылок в крейтах не выполнены.
[Набор приёмочных fixtures S14](../../research/stage-2-libs.md#приёмка-s14)
закрепляет отказ до опасного чтения или записи.
Системные функции полной распаковки библиотек здесь не нужны.
Пароль передаётся в отдельном кадре приватного канала с ограниченным
сроком жизни. Аргументы процесса, логи и обычные сообщения прогресса
пароль не содержат.

## Поставка helper

Решение координатора для 2a — только macOS arm64, по образцу
[Remote Hub](../../../remote-hub/helper/Cargo.toml).

| Платформа | Измеренный размер | Сборка и поставка | Подпись и карантин |
| --- | --- | --- | --- |
| macOS arm64 | Пробный бинарник 1 052 208 байт. Helper Remote Hub для ориентира 13 063 248 байт. Размер релиза Commander пока неизвестен | Нативный arm64 runner в CI, `cargo build --release --locked --target aarch64-apple-darwin`. Один helper и файл SHA-256 в Git на релиз. Оценка текущего добавления около 1,0 МиБ сырого бинарника на релиз, фактический размер проверяется после сборки и подписи. Для пробы оценка одного Git-объекта без дельт — 471 808 байт (zlib, level 1). Каждый релизный бинарник добавляет объект в историю | Проба подписана ad-hoc, `codesign --verify` прошёл, `com.apple.quarantine` отсутствует. На чистой машине проверить подпись релиза и запуск при реальном карантине. Порядок подписи и нотарификации, если их потребует канал поставки, подтвердить до выпуска. Атрибут карантина автоматически не удалять |
| macOS x64, Linux, Windows | — | Артефактов и кросс-сборки в 2a нет. Сообщение «Архивы недоступны: нет helper для платформы». JS-fallback отсутствует | — |

До `spawn` проверять наличие, тип файла и SHA-256 выбранного helper по
поставленной контрольной сумме. Отсутствие, некорректные метаданные или
несовпадение блокируют запуск. Пример — [тесты целостности Remote Hub](../../../remote-hub/src/adapters/bb/helper-integrity.test.ts).
Запуск по абсолютному пути, ограниченные кадры и срок жизни процесса.
Отмена и выгрузка плагина завершают процесс и закрывают потоки.
Отдельный процесс локализует отказ и расход памяти. Для изоляции доступа
к ФС нужны дополнительные ограничения ОС.

## Хеши, поиск, diff

SHA-256 — `node:crypto` по байтам провайдера. Поиск по содержимому —
в серверном адаптере, с явным согласием для remote, оценкой чтения, лимитами
и отменой между чанками. Для построчного diff предлагается `diff` 9.0.0
(BSD-3-Clause), с ограничением входа, `timeout` и `maxEditLength`.
При превышении бюджета показать, что сравнение прервано.

## F4 и экспериментальные API

Основной путь F4 — зарегистрировать свой `slots.fileOpener` с
`extensions: []` и передать его ID в `experimental_openFilePreview`
с целью `kind: "host"`. Пустой список расширений оставляет редактор
доступным только при явном вызове. Редактор загружает и сохраняет
временную копию через RPC Commander. Сервер связывает запрос с
заданием, идентификатором копии, владельцем и хостом. Путь, переданный UI,
не даёт права на произвольное чтение или запись. Сохранение копии и
«Записать обратно» — два разных действия. Перед записью оригинала
сверяются его хеш и mtime. Расхождение или удаление приводят к конфликту.

Копия принадлежит заданию и создаётся host entry только под
`experimental_paths.dataDir`. При недоступности этого каталога F4
недоступен. `bb.server.experimental_dataDir` предназначен только для
чтения мигрируемых данных BB, а `bb.storage.experimental_directory()`
отсутствует в SDK 0.6.132. Если копия создана, но явный opener недоступен,
предусмотрен fallback с путём или file mention. Результат
`experimental_openFilePreview` показывает принятие навигации, поэтому
доступность редактирования проверяется отдельно.
