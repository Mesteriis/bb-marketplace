# Makosh Mail — Slice 3g (BB threads and tasks from mail, project files, thread results as drafts, Dev view, dev links, code blocks, patches, incident threads, project binding, mail rules) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use `- [ ]`.

**Goal:** On the owner's click, Mail hands a message or a conversation to BB: a new agent thread in a chosen project (the exact prompt and the project's permission mode shown first, linked both ways), a task on the owner's local Taskboard board or, failing that, a 3f local task with a note, an attachment saved create-only into the project's working tree, a patch reviewed per file and handed to an agent thread in a fresh managed worktree, and an alert opened once as an incident thread. Project and thread files become attachments only by the owner's pick, and a thread's result or one assistant message becomes a Mail draft, never a sent mail. GitHub, GitLab, CI and monitoring mail is classified locally at sync and grouped in a **Dev** view; repository, PR and issue links are listed by their real URL and mapped to BB projects; code blocks render with BB's highlighter and survive writing and replying. Conversations are bound to a project by the owner (or by owner-made binding rules) and shown in a **Projects** view and in a **Mail** section of BB's thread Info tab. With `mailRules` on, owner-made rules prepare (or, opted in per rule, start in a managed worktree with `accept-edits`) capped agent threads from new incremental Inbox mail. Every text that reaches BB passes one builder (`bb-text.ts`: 3f redaction, AI access scope, `UNTRUSTED_NOTICE`, quotes stripped) and writes a content-free agent-log row. Nothing in 3g writes to an IMAP server, sends mail, runs a command or makes an HTTP request.

**Architecture:** Same layers. Core gains pure modules: `file-names.ts` (`sanitizeFileName`, `safeContentType` moved from `downloads.ts`), `project-paths.ts` (`projectRelativePath`, `keepBothName`, `sensitiveName`, `agentInstructionName`), `projects.ts` (`repoRefOf`, `workingTree`, `ProjectInfo`), `bb-text.ts` (`threadPrompt`, `taskText`, `incidentPrompt`, `rulePrompt`, `threadTitle`, `metadataFor`), `dev-notify.ts`, `dev-links.ts`, `code-blocks.ts`, `markdown-doc.ts`, `patch.ts`, `alerts.ts`, `mail-rules.ts`; `agent-text.ts` gains `scanHtml` and `bodyPlainText`; `agent-log.ts` gains actors, tools and outcomes; `compose-doc.ts` keeps `codeBlock` and `code`. Store gains migration element 11 (`messages` dev columns and `list_id`, `bb_links`, `conversation_projects`, `project_bindings`, `incident_threads`, `mail_rules`, `rule_runs` with `starting`, `compose_attachments.origin`, `mail_tasks.note`, the `rule_runs_bb_thread` index). Adapters gain `bb-projects.ts` (`ProjectDirectory` over `bb.sdk.projects` / `files`), `bb-threads.ts` (spawn, send, output, storage files, attachments upload, default execution options) and `taskboard-target.ts` (`plugins.list` / `callRpc`); sync classifies new rows and the bulk backfill fills `list_id`. Server gains 31 owner RPCs, settings `devNotifications`, `attachmentFolder`, `patchFolder`, `taskTarget`, `mailRules`, rule evaluation after each ok round, rule-thread gating in `configure`, tools and CLI, and day notices of kind `rule`. UI gains the BB thread, task, save-to-project, file-picker and patch dialogs, the alert card, links strip, Project chip, code blocks with injected host components, the composer's code block and BB attachments, the Dev and Projects views, the Ready-to-start strip, Rules and BB integration settings, and three BB surfaces registered in `app.tsx` (thread action **Email the result**, message action **Email this**, thread Info section **Mail**).

**Spec:** `docs/superpowers/specs/2026-11-16-mail-slice-3g-bb-integration-design.md` — its "Resolutions after the builder check" (1–18) override every section above them; the owner accepted all decisions on 2026-11-16 and the *(owner defaults)* items as recommended. Slice 1, 2 and 3a–3f specs (with their resolutions) still hold where 3g does not change them.

## Global Constraints

- Slice-1, slice-2 and 3a–3f global constraints still bind (see `docs/superpowers/plans/2026-11-14-mail-imap-first-slice.md`, `2026-11-15-mail-folders-images-actions.md`, `2026-11-15-mail-slice-3a-organize.md`, `2026-11-15-mail-slice-3b-compose.md`, `2026-11-15-mail-slice-3c-agent-send-translate.md`, `2026-11-15-mail-slice-3d-sending-polish.md`, `2026-11-15-mail-slice-3e-inbox-triage.md`, `2026-11-16-mail-slice-3f-agent-and-mail.md`), extended. **No new server writes, sends or HTTP in 3g:** no IMAP command that writes, no SMTP send, no outbound HTTP; `src/adapters/bb/one-click.ts` stays the only HTTP client.
- **The plugin runs no command.** No `bb.sdk.terminals`, no host entry (`bb.hosts`), no `git`, no unpacking, no opening of saved files. Patches reach an agent only as an uploaded attachment with a fixed instruction (spec resolution 10).
- **No text reaches BB outside `bb-text.ts`.** Every thread prompt, title, task title and description, incident or rule text and alert update is built there: 3f `redactSecrets` over each whole field before any cut, the AI access scope checked first (`out_of_scope`), quotes stripped through `stripQuoted`, the renderer's own `UNTRUSTED_NOTICE` and no second one (spec resolution 8). Plugin metadata holds ids only and is never read back for a decision (spec resolution 4).
- **Nothing starts without the owner** except a thread by an owner-made rule in mode `start` with the per-rule opt-in, inside the caps, in a managed worktree with `accept-edits` (spec resolutions 1, 13, 15). Rules see only `newInbox` minus `returning` of an ok round (spec resolution 3).
- **Files:** writes only inside the chosen project's working tree through `projectRelativePath`, create-only (`files.read` first, `expectedSha256: null`), `mode: 0o644`, Replace only with the shown `sha256` (spec resolution 5); no dot-first folder, no `.git`, shortcut and agent-instruction names get `.txt` (spec resolution 11).
- **No mail content in the agent log, plugin logs, realtime or errors.** `agent_log` holds ids, counts, codes and BB thread, task or rule ids — never a path, project name, title, prompt or file name. Realtime carries `{ token }` only.
- Every 3g RPC is owner-only (`refusePluginCaller`, `server.ts` 671). Output keys never match `/pass|secret|seal|key/i` (`sensitiveName`, `alertRef`, `patchRef`).
- MIGRATIONS: elements 0–10 frozen and hash-pinned ("shipped migration elements are unchanged" in `src/adapters/bb/sqlite-store.test.ts` pins `MIGRATIONS.slice(0, 11)`). Append element 11 only; never edit or reformat an earlier element. Element 11 joins the pin in Task 15 (`MIGRATIONS.slice(0, 12)`). New tables keep ISO TEXT timestamps and carry no `REFERENCES` clause; deletes are explicit.
- `src/core` and `src/ui` stay host-free. `tests/architecture.test.ts` is unchanged. `experimental_SourceCode` / `experimental_Diff` are imported only in `app.tsx` and injected as render props (spec resolution 6). `src/ui` never imports `sonner`.
- SDK calls use the installed declarations' shapes (spec resolution 7): text input items `{ type: "text", text, mentions: [] }`; `threads.send` with `mode: "queue-if-active"`; `limit` as a string for `threads.storageFiles` and `projects.files`.
- No new dependency (TipTap's code block ships in StarterKit). `package.json` changes only in `description` / `bb.description` (Task 15); `THIRD_PARTY_NOTICES.md` untouched unless code is ported (none planned).
- Tests colocated next to the code (`*.test.ts(x)`); fixtures use made-up addresses on `example.com` / `example.org`, made-up repositories (`example-org/demo`), made-up text and made-up secrets joined from pieces at run time (3f review resolution 5). SDK calls in server and adapter tests go through `createFakePluginHost` / `createFakeSdk` overrides that record their arguments. Timing tests time one call (one page) with a generous bound and never time seeding.
- Every task leaves `npm run check` green and is committed on `feat/mail-imap-slice` with the trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. `git add` only the task's own files (the tree holds unrelated uncommitted changes, and other sessions commit here). Never push, tag or publish; never touch the installed plugin, `.worktrees/live`, makosh-ai or Taskboard.

## Review Focus

- **One builder, no leaks:** every hand-off (`bb_thread_start`, `task_from_mail` to Taskboard and to local, `incident_start` / `incident_append`, `patch_handoff`'s commit message, rule Prepare and Start) gets its text from `bb-text.ts`; the canary test runs each one against recording fakes of `threads.spawn` / `send`, `plugins.callRpc` and `projects.attachments.upload` and finds no canary in any recorded input, metadata, `agent_log`, log or realtime payload. Tests in Tasks 2, 10, 11, 12.
- **Renderer facts hold:** quotes stripped before rendering (`bodyPlainText` → `stripQuoted`), exactly one `UNTRUSTED_NOTICE` per rendered message, the real notice text, the excerpt and commit message framed once. Tests in Task 2.
- **Paths cannot escape:** absolute, `..`, backslash, drive letters, `~`, `.git` in any case, dot-first segment, too deep or too long, a segment not equal to its sanitized form; shortcut and agent-instruction names get `.txt`; `keepBothName` numbering to `(99)`; the adapter's absolute-prefix re-check. Tests in Tasks 1, 9.
- **Create-only is real:** `files.read` before every write, any content → `exists`, a not-found error → write with `expectedSha256: null`, a `conflict` outcome → `exists`, other read errors → `failed`; Replace only with the shown sha; a reported symlink refuses; the "turned off in this version" switch disables saving. Tests in Tasks 9, 10.
- **Rules are narrow and capped:** candidates only from `newInbox` minus `returning`; never on `inserted`, backfill, initial sync or reset; scope, bulk, own-address and per-message uniqueness; `starting` inserted with the cap check in one transaction; 3/hour and 10/day per rule, 20/day in all, one per conversation per rule per 24 h, counted across `rule_delete`; alert-class rules through incident dedup; Start only in a managed worktree with `accept-edits`, never a checkout fallback. Tests in Tasks 5, 7, 12.
- **Rule threads get no mail:** `configure` keyed on `ctx.thread.id`, each tool's `execute` on `ctx.threadId`, the CLI in a thread — all through `rule_runs.bb_thread_id`; forged metadata on a normal thread changes nothing, metadata on a rule thread removed changes nothing. Tests in Task 12.
- **Mail origin from Mail's rows:** `draft_from_bb` replies only when `bb_links` ties the BB thread to a still-stored message; metadata is ignored. Tests in Task 10.
- **Taskboard fails soft:** absent, disabled, any `callRpc` error or malformed answer → local fallback offered; Jira boards left out; only Taskboard refusals shown as "Taskboard: …"; the `callRpc` input is the redacted `taskText`. Tests in Tasks 9, 10.
- **Patches are refused or warned correctly:** quoted and escaped paths, `rename` / `copy` from and to, `---` / `+++`, `.git` case-insensitive, the new warning paths, 1 MB and 200 files; `patchRef` re-checked on save and hand-off; hand-off uploads, never writes into the tree. Tests in Tasks 5, 11.
- **Code and model-free classification:** fenced, indented, diff and log blocks with negatives; `<pre>` and `href` from `scanHtml` without a DOM; the composer's code block round-trips HTML and plain; dev classifier negatives (a person writing about GitHub, github.com marketing). Tests in Tasks 3, 4, 8.
- **Explicit deletes and prunes:** `deleteAccount` deletes the account's `bb_links`, `conversation_projects` and `rule_runs`; `deleteRows` deletes `bb_links` and `rule_runs` of removed messages; the daily purge drops gone conversations' bindings, bindings to unknown projects after 30 days, `rule_runs` older than 30 days (after counting), `incident_threads` older than 90 days, ready runs older than 7 days → `expired`. Tests in Task 7.
