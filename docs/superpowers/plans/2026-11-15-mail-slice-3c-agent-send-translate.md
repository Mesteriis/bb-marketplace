# Makosh Mail — Slice 3c (agent send with confirmation, translation) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use `- [ ]`.

**Goal:** Agents in a BB thread propose a new message, reply, reply all or forward through one native tool, `mail_propose`; the owner sees a confirmation card in that thread with the whole message and the prompt-injection flags, and Send queues exactly what the card showed through the 3b outbox with `origin = 'agent'` and the 10 s Undo; Open in Mail turns it into an ordinary draft; Cancel discards it. A Translate action in the reading pane, started only by the owner, streams a plain-text translation of the message through makosh-ai with the provider and model the owner chose, cached per message and language, with clear degradation when makosh-ai or the provider is unavailable.

**Architecture:** Same layers. Core gains pure proposal logic (`agent-propose.ts`: canonical content and hash, recipient merge and flags, hidden-text and link scanning, caps, the proposal state machine, the submit-value parse, the server-built plain-text quote), pure translation logic (`translate.ts`: the `Translator` port, source, prompt, languages, error kinds), the split of 3b's `prepareCompose` / `newCompose` into plan + create, and the proposal use cases (`agent-proposals.ts`) over new `MailStore` methods. Store gains migration element 5 (`compose_drafts.proposal_id`, `agent_proposals`, `translations`). Adapters gain an SSE reader and the makosh-ai translator over `bb.sdk.plugins.callRpc`, and in-memory translation jobs. Server gains the tool, its `requestInput` card flow with the submit check inside `describeSubmission`, the proposal-draft refusals in the compose handlers, two proposal RPCs and six translation RPCs. UI gains the card (`pendingInteraction` `agent-send`), the settled thread row (`experimental_timelineRenderer`), the translation block and its settings dialog; toasts stay in `app.tsx`.

**Spec:** `docs/superpowers/specs/2026-11-15-mail-slice-3c-agent-send-translate-design.md` — its "Resolutions after the builder check" override every section above them; the owner decided all *(owner)* items on 2026-11-15. Slice 1, 2, 3a and 3b specs (with their resolutions) still hold where 3c does not change them.

## Global Constraints

- Slice-1, slice-2, 3a and 3b global constraints still bind (see `docs/superpowers/plans/2026-11-14-mail-imap-first-slice.md`, `2026-11-15-mail-folders-images-actions.md`, `2026-11-15-mail-slice-3a-organize.md`, `2026-11-15-mail-slice-3b-compose.md`), extended. Server writes allowed in 3c = the 3b set plus the SMTP submission (and 3b's Sent-copy step) of an agent proposal the owner confirmed in its card. No new IMAP write: a proposal draft never gets a server copy.
- **Only the card's submit reaches `queueSend` with `origin: "agent"`.** No tool argument, tool result, other RPC, settings value, realtime event or restart does. The tool creates a proposal and waits; it never confirms. Accepted limit (spec resolution 1): a shell-access `client` caller can read the card, call `proposal_view` and answer the form, start and read translations, and rotate a view token; mitigations are mandatory — `agentPropose` off by default, the 10 s Undo with a toast on any open Mail page and in the thread row, the card caps, plain words in README / `PLUGIN_OVERVIEW.md` / `skills/mail/SKILL.md`.
- **No mail content in logs, realtime, errors, the persisted form row, the form payload or agent text.** Never recipients, subjects, bodies, file names, translations, view tokens or content hashes. The form payload and the settled description payload are `{ proposalId }` (plus `contentHash` in the pending payload only, which the card needs and the agent already cannot use without a token); the tool result is a fixed sentence; logs carry ids, states and error kinds; `outbox-changed` stays `{ accountId, id, state }`; translations travel only in `translate_poll` responses.
- **Agents get exactly one new tool.** `mail_propose`, offered by `bb.agents.configure` only while `agentPropose` is on (independent of `agentTools`), and `execute` re-checks the setting. No translate tool, no CLI command, no mention provider change; translations are not added to `mail_read`. Every new RPC is registered with `{ experimental_discoverable: false }` and starts with `refusePluginCaller(context)`.
- **makosh-ai over RPC only.** `bb.sdk.plugins.callRpc({ pluginId: "makosh-ai", method: "ai.v1.*" })` from the server; never import its files, never read its directory at runtime. The makosh-ai additions (`ai.v1.providers`, optional `projectId`, distinct busy / bridge-missing codes) are not tasks here (spec resolution 4). No provider id or model id written into code as a default; no "Claude" as the fixed translator in any text.
- **Model output is text.** A translation is a React text child in `white-space: pre-wrap`, never HTML, Markdown, a link or `dangerouslySetInnerHTML`, and never inside the message iframe.
- MIGRATIONS: elements 0–4 frozen (shipped, hash-pinned by BB and by "shipped migration elements are unchanged" in `src/adapters/bb/sqlite-store.test.ts`). Append element 5 only; never edit or reformat an earlier element. New tables keep ISO TEXT timestamps and carry no `REFERENCES` clause; deletes are explicit (spec resolution 17).
- `src/core` and `src/ui` stay host-free. `tests/architecture.test.ts` is unchanged: no allow-list entry is added. `src/ui` never imports `sonner`.
- No new dependency. `package.json` changes only in `description` / `bb.description` (Task 11); `THIRD_PARTY_NOTICES.md` untouched unless code is ported.
- Tests colocated next to the code (`*.test.ts(x)`); fixtures use made-up addresses on `example.com` / `example.org` and made-up text only; SSE fixtures are synthetic.
- Every task leaves `npm run check` green and is committed on `feat/mail-imap-slice` with the trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. `git add` only the task's own files (the tree holds unrelated uncommitted changes). Never push, tag or publish; never touch the installed plugin, `.worktrees/live` or makosh-ai.

## Review Focus

- **Forged or stale confirmation:** a wrong `proposalId`, a wrong hash, a missing, old or reused token, a token rotated by a second `proposal_view`, a submit after expiry, two submits racing, a hidden draft changed in the store after the view — each yields no outbox row, and only the latest view's token can submit. The check runs once, inside `describeSubmission`, and its title is true when persisted. Tests in Tasks 4 and 7.
- **Hidden drafts unreachable:** every `compose_*` RPC (including `compose_open` by `draftId` and by `draftMessageId`, and `compose_attachment_finish` through an upload) answers `not_found` for a proposal draft; no server copy is ever written for one; `listDrafts`-driven ticks skip it. Tests in Tasks 4 and 7.
- **What was shown is what is sent:** the canonical content (From display name included) hashes the same at view, at submit and against the draft `queueSend` builds from; the quote is server-built plain text and `importHtml` is null; the MIME equals `queueSend` of the same draft. Tests in Tasks 1, 4 and 7.
- **Prompt injection on the card:** agent display names dropped; bidi and zero-width characters revealed; IDN shown as punycode; "New address" means never sent to by the owner; added-by-agent only beyond the Reply rules; Bcc row always present; scheme-less links listed; long lists collapsed with one bulk acknowledgement. Tests in Tasks 1 and 9.
- **Undo and failure paths:** Undo or Edit on an agent row turns the draft into an owner draft (`proposal_id` cleared, proposal `opened`) in one transaction; a `queueSend` refusal after the click does the same with the fixed reason; restart never confirms. Tests in Tasks 4, 5 and 7.
- **Translation leakage and parsing:** only subject and body reach the model, nonce-framed; SSE split at every byte boundary (multi-byte characters, events across chunks); `contentType: null` parsed; `cancel` always called; the output character cap cancels the stream; error mapping per spec resolution 16. Tests in Tasks 2, 6 and 8.
- **Explicit deletes:** translations go with every message removal path and account removal; proposals go with account removal. Tests in Task 5.
