# Makosh Mail — Slice 3d (signatures, aliases, pre-send check, undo, templates) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use `- [ ]`.

**Goal:** Each sending identity (an account's own address and each alias the owner adds by hand or from suggestions) has an optional signature that a new draft gets at the end and a reply or forward gets above the attribution and quote; From offers every identity and a reply starts from the address the original came to. Send runs four advisory checks (forgotten attachment, empty subject, a recipient outside the conversation, a new recipient) and shows a "Before you send" dialog with Fix and Send anyway. After archive, delete, spam, not spam, move or a flag or read change, a toast and the `z` key undo the last action, by moving rows back only where they still are and, on Gmail only, by UID COPY. Named templates are written in settings and inserted at the cursor; agents list them and name one in `mail_propose`. Agent proposals carry the identity's signature and template, and the card shows the alias, template, signature and checks.

**Architecture:** Same layers. Core gains pure modules: `compose-signature.ts` (normalization, placement, swap, own-signature strip) with the `signature` block in `compose-doc.ts`; `identities.ts` (identities of an account, own addresses, the reply-from rule, alias suggestions, send-check transitions); `templates.ts` (name keys, normalization without quotes, text form); `presend.ts` (the four checks); `undo.ts` (records, the per-row plan). Use cases in `compose.ts`, `compose-outbox.ts` and `agent-proposals.ts` take the draft's identity for From, Message-ID and hash. Store gains migration element 7 (`accounts.signature_json`, `identities`, `compose_drafts.from_address`, `messages.delivered_to_json`, `agent_proposals.template_name`, `templates`, `sent_recipients`). Adapters gain `FolderSession.copyMessages`, Delivered-To / X-Original-To parsing, the SMTP `command` on `SendError`, the in-memory `UndoBook`, and send-check resolution after each sync round. Server gains 11 owner RPCs, `undoId` on `message_action`, `runUndo` through the account queue, `compose_check`, the `mail_templates` tool and the `mail_propose` additions. UI gains the mail settings dialog, the signature node, From by identity, the templates popover, the pre-send dialog, the undo toasts and `z`, and the card additions; toasts stay in `app.tsx`.

**Spec:** `docs/superpowers/specs/2026-11-15-mail-slice-3d-sending-polish-design.md` — its "Resolutions after the builder check" override every section above them; the owner decided all *(owner)* items on 2026-11-15. Slice 1, 2, 3a, 3b and 3c specs (with their resolutions) still hold where 3d does not change them.

## Global Constraints

- Slice-1, slice-2, 3a, 3b and 3c global constraints still bind (see `docs/superpowers/plans/2026-11-14-mail-imap-first-slice.md`, `2026-11-15-mail-folders-images-actions.md`, `2026-11-15-mail-slice-3a-organize.md`, `2026-11-15-mail-slice-3b-compose.md`, `2026-11-15-mail-slice-3c-agent-send-translate.md`), extended. Server writes allowed in 3d = the 3c set plus: SMTP submission with a From the owner chose among the account's identities, and UID COPY by undo, only on a session whose `capabilities().gmail` is true and only from a folder that is not Trash or Spam (spec resolution 1). Undo otherwise only queues moves through `queueMove`; it never sets `\Deleted` and never expunges.
- **No From the owner did not choose.** No sync, suggestion, agent or migration adds an active identity. Only `identity_add` (an owner RPC) does. An agent picks an alias only by naming it for a new message or through the reply-from rule, and the card shows it before Send.
- **Every check is advisory.** `compose_check` failing in any way lets the send go on; nothing in 3d refuses a send because of a check.
- **No mail content in logs, realtime, errors or agent text.** Never addresses, signatures, template text, check phrases or subjects. Logs carry ids, kinds and counts; `mail-changed` and `outbox-changed` payloads are unchanged. Texts naming an alias go to the page only (Outbox rows, the From list, settings).

New tables keep ISO TEXT timestamps and carry no `REFERENCES` clause; deletes are explicit.
- `src/core` and `src/ui` stay host-free. `tests/architecture.test.ts` is unchanged: `@tiptap/core` is already allowed in `src/ui`. `src/ui` never imports `sonner`.
- No new dependency. `package.json` changes only in `description` / `bb.description` (Task 15); `THIRD_PARTY_NOTICES.md` untouched unless code is ported (none planned).
- Tests colocated next to the code (`*.test.ts(x)`); fixtures use made-up addresses on `example.com` / `example.org` and made-up text only; header fixtures with Delivered-To and X-Original-To are synthetic.
- Every task leaves `npm run check` green and is committed on `feat/mail-imap-slice` with the trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. `git add` only the task's own files (the tree holds unrelated uncommitted changes). ## Review Focus

- **Undo never destroys and never lands elsewhere:** `planUndo` for every row of the spec table; `cancelMove` is a compare-and-swap; an undo racing a sync round ends as a move back, never as a lost row; a detached row gets its reverse move after reattach; COPY only with `capabilities().gmail` and never from Trash or Spam, `moveMessages` otherwise; UIDVALIDITY mismatch skips; a fake session records every command and none is `\Deleted` or EXPUNGE; refused groups keep the slot; failed copy groups go back into it; a stale or foreign `undoId` does nothing. Tests in Tasks 4, 11.
- **From is the owner's choice:** `compose_save` refuses a foreign `fromAddress`, an account switch resets it, `queueSend` refuses a removed alias with `from_unknown`, the Drafts copy falls back to the own address; envelope sender equals header From; the reply-from rule searches only the source's account; an agent's `accountId` naming another identity for a reply refuses with `account_mismatch`. Tests in Tasks 2, 6, 7, 10.
- **Signature placement and quotes:** `-- ` only when the signature is last; replies and forwards separate it by a blank line and the class only; Reply / Reply all to own mail strip the own signature, Forward keeps it; a foreign message's `makosh-signature` class is removed before import and on paste; the node cannot nest. Tests in Tasks 1, 6, 13.
- **What the card shows is what is sent:** the signature and the template blocks are inside `doc`, so the content hash covers them; `draftHash` uses the identity's name and address; `links` covers signature and template link `href`s; a later template edit does not change a pending proposal. Tests in Tasks 7, 10, 14.
- **Pre-send check never blocks:** a `compose_check` error sends; Cmd/Ctrl+Enter is inert in the dialog; conversation participants are never "new"; the Russian false positives stay quiet. Tests in Tasks 3, 13.
- **Leakage:** a spy logger and a realtime recorder over an alias send, a refused alias, an undo, a check and a template proposal see no address, signature, template text or phrase. Tests in Tasks 10, 11.
- **Explicit deletes:** `identities` and `sent_recipients` rows go with `deleteAccount`; templates are global. Tests in Task 8.
