# Makosh Mail — Slice 3e (IDLE, notifications, unsubscribe, snooze, block, filters, agent triage) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use `- [ ]`.

**Goal:** While BB runs, each account keeps one read-only IMAP IDLE connection on its Inbox, and a change there wakes an Inbox-only sync round within seconds. New unread mail from someone the owner has written to (not bulk, not blocked, not own) shows a toast with the sender's name and address and **Open** in every BB window, outside quiet hours; a returning snoozed message toasts the same way. A message with `List-Unsubscribe` offers **Unsubscribe**: on iCloud and Gmail an RFC 8058 one-click POST when the provider's Authentication-Results vouch for a DKIM signature covering both list headers, else an unsubscribe email through the 3b outbox with Undo. **Snooze** (`b`) moves a conversation's Inbox mail to a Snoozed folder created on the owner's confirmation and moves it back unread at the chosen time. **Block** adds a global address or domain rule, moves matching Inbox mail to Spam and moves new Inbox mail from that sender to Spam after each round. Toggles **Unread**, **Flagged**, **Attachments** narrow the list. With `agentTriage` on, an agent lists the Inbox and proposes a batch; the owner ticks a subset on a card and only those run through the owner's own paths, undoable from the thread row.

**Architecture:** Same layers. Core gains pure modules: `unsubscribe.ts` (parsing, `trustOf`), `blocking.ts` (rules, candidates, public domains), `notify.ts` (`notifiable`, quiet hours), `idle-policy.ts` (backoff, debounce), `snooze.ts` (`planSnoozes`, presets), `triage.ts` (validation, caps, hash, agent result text); `undo.ts` widens to per-group kinds. `sync.ts` gains the Inbox-only round, `newInbox` and unsubscribe info at sync; `bulk-backfill.ts` a second pass. Store gains migration element 8 (`messages.unsubscribe_json`, `accounts.snooze_folder`, `compose_drafts.purpose`, `snoozes`, `block_rules`, `unsubscribes`, `spam_seen`, `triage_batches`, `triage_items`). Adapters gain `ImapGateway.watchFolder` / `createFolder`, `FolderSession.fetchHeaderFields`, `idle-service.ts`, `new-mail-book.ts`, `one-click.ts`, `snooze-clock.ts` and the sync loop's pending map. Server gains 13 owner RPCs, settings `instantMail`, `notifyNewMail`, `quietHours`, `agentTriage`, the tools `mail_inbox` and `mail_triage`, and the `agent-triage` card. UI gains filter toggles, unsubscribe, snooze and block dialogs, `b`, the Blocked senders section, `useNewMailToasts` and the triage card and row; toasts stay in `app.tsx`.

**Spec:** `docs/superpowers/specs/2026-11-15-mail-slice-3e-inbox-triage-design.md` — its "Resolutions after the builder check" (1–26) override every section above them; the owner decided all *(owner)* items on 2026-11-15. Slice 1, 2, 3a, 3b, 3c and 3d specs (with their resolutions) still hold where 3e does not change them.

## Review Focus

- **One-click trust cannot be forged by the sender:** only trusted authserv-ids per preset, only A-R inside the provider's top block and above the topmost `DKIM-Signature`, a conflicting `fail` wins, `header.d` or the `header.i` domain, signature chosen by `s=` and `b=` prefix with `d=` equal to or a parent of the signer, whitespace stripped in `h=` and `b=`, both list headers in `h=`, domain sense, repeated list headers → `not_covered`, `other` preset → `untrusted_provider`. Tests in Task 1.
- **The HTTP client cannot be turned against the owner:** IPv4 special registry and the IPv6 allow-list (including 64:ff9b::/96, 2002::/16, Teredo, mapped forms), both lookup callback shapes, the connection goes to the vetted address, no proxy env, no redirect followed, no cookie sent, body ≤ 16 KiB drained and dropped, timeouts, rate limits; no other module imports `node:https`. Tests in Task 9.
- **IDLE never writes and never amplifies a lockout:** EXAMINE only, no session commands exposed, `idle()` returning `false` → `dropped`, `auth` stops the watch and never retries, `throttled` → 15 min, backoff and reset, dead peer within about 150 s, abort ends every watch promptly. Tests in Tasks 2, 8, 9.
- **Inbox-only rounds never lose account state:** no listing, `lastSyncAt` unchanged, the full round's `lastError` kept, `assignThreads` run, only Inbox pushes, `"all"` wins in the pending map. Tests in Tasks 6, 9.
- **Toasts only for the right mail:** `newInbox` excludes initial, reset, reattach, re-home, reconcile backfill and returning rows; every `notifiable` rule; quiet hours; a returning snooze toasts by the same filter; realtime `{ token }` only; the badge survives a toast failure. Tests in Tasks 2, 6, 10, 15.
- **Snooze and block only move, and only what they should:** every row of the snooze state table, detached rows wait, a removed snooze folder clears `snooze_folder`; block moves only matching Inbox-role rows, never a message rescued from Spam (`spam_seen`), never own mail; a fake session command log has no `\Deleted`, no EXPUNGE. Tests in Tasks 3, 7, 12.
- **Undo of mixed batches:** each group undone by its own `kind` and `change`; `mergeRecord` merges on id regardless of action; snooze undo deletes its snooze rows; block undo deletes its rule. Tests in Tasks 4, 12, 13.
- **One hidden-draft predicate:** `isHiddenDraft` at every visibility check, purpose drafts never reach the server Drafts folder or a compose RPC, Undo deletes them, no origin `agent` row without a proposal id. Tests in Tasks 6, 11.
- **Triage applies only what the owner ticked:** describeSubmission checks, positions, unavailable items, created folders only for ticked accounts, reply items refused with `agentPropose` off and running nothing, unsubscribe items unticked by default, `interrupted` after a restart, agent result has ids and counts only. Tests in Tasks 3, 13, 15.
- **Explicit deletes:** `snoozes`, `unsubscribes`, `spam_seen` and `triage_items` with `deleteAccount`, `snoozes` with `deleteRows`, empty `triage_batches` after account removal; `block_rules` global. Tests in Task 7.

### Task 1: Core unsubscribe parsing and trust (pure)

**Files:** new `src/core/unsubscribe.ts` (+ colocated `unsubscribe.test.ts`); `src/core/index.ts` exports.

**Produces:**
- `type HeaderLine = { key: string; value: string }` (lower-case key, unfolded value, message order); `UNSUBSCRIBE_HEADER_FIELDS = ["From", "List-Id", "List-Unsubscribe", "List-Unsubscribe-Post", "Authentication-Results", "DKIM-Signature", …PROVIDER_TRACE_HEADERS names]` for the backfill fetch.
- `type UnsubscribeTrust = "covered" | "not_covered" | "no_dkim" | "untrusted_provider"`; `type UnsubscribeInfo = { listKey: string; listName: string | null; https: string | null; oneClick: boolean; mailto: { address: string; subject: string; body: string } | null; trust: UnsubscribeTrust }`; `UNSUBSCRIBE_INFO_MAX_BYTES = 4 * 1024`.
- `parseListUnsubscribe(headers: HeaderLine[]): { https; mailto; oneClick; repeated: boolean }` (spec "Parsing at sync": at most 5 angle-bracketed entries ≤ 2 048 characters; first `https:` and first `mailto:`; `http:` and other schemes ignored; https without userinfo, with a DNS host and no port or 443; mailto with exactly one valid ASCII-domain address, subject one line ≤ 200 default "unsubscribe", body ≤ 1 000, other parameters dropped; `oneClick` only for an exact `List-Unsubscribe=One-Click` with `https` set; `repeated` when either list header occurs twice — spec resolution 11).
- `TRUSTED_AUTHSERV: Record<AccountPreset, readonly string[]>` (`gmail: ["mx.google.com"]`, `icloud: []` until pinned live, `other: []` — spec resolutions 3, 4); `PROVIDER_TRACE_HEADERS: Record<AccountPreset, readonly string[]>` (resolution 12; name patterns with a trailing `*` for `X-Google-*`, `X-Gm-*`).
- `trustOf(headers: HeaderLine[], preset: AccountPreset, fromDomain: string | null, httpsHost: string | null): UnsubscribeTrust` per spec "Trust rules" items 3–5 as changed by resolutions 10–12: provider top block, all trusted-id A-R in it above the topmost `DKIM-Signature`, `dkim=pass` by `header.d` or the `header.i` domain, a `fail` for the same signature in another counted header → `no_dkim`, signature by `s=` / `b=` prefix / `d=` equal or parent, a unique `d=` match when neither is given, whitespace removed in `h=` and `b=`, both list headers in `h=`, domain sense against the signature's `d=`.
- `unsubscribeInfoOf(headers: HeaderLine[], preset, from: { name: string | null; address: string }): UnsubscribeInfo | null` — null without `List-Unsubscribe` or with no headers; `listKey` from `List-Id` (lower case) else the From address; `listName` revealed (`revealHidden`) and cut to 80; `repeated` → `trust: "not_covered"` and no mailto; serialized size over 4 KiB → null.
- `offeredMethods(info: UnsubscribeInfo): { oneClick: { host: string } | null; mailto: { address; subject; foreignDomain: boolean } | null }` (one-click only with `oneClick && trust === "covered"`; `foreignDomain` when the mailto domain is neither the From domain nor a parent).
