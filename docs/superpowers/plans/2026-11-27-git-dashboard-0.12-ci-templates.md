# Makosh Git 0.12 — CI-шаблоны

Ветка `feature/bb-git-dashboard-ci-templates` от main 0ccfaf13. Дизайн: строка 0.12.0 и §13.4 (шаблоны лежат в плагине и
версионируются с ним; свои — из настроек или папки; в шаблонах только каркас и параметры, без секретов, `.env`, адресов,
хостов, токенов, имён клиентов и кода проектов). Определение стека из этого среза переиспользует 0.13 (скаффолды).

## Решения

- Стек определяется по файлам локальной копии в `origin/<ветка по умолчанию>` (как последний раз получена), иначе в `HEAD`: список отслеживаемых путей и несколько манифестов
  (`package.json`, `pyproject.toml`, `go.mod`, `Cargo.toml`, `pom.xml`, `build.gradle*`, `*.csproj`, `Dockerfile`),
  каждый не больше 64 KB, без запуска хуков. Из манифестов берутся параметры по умолчанию:
  менеджер пакетов и версия Node, наличие скриптов test/build/lint, инструмент Python (uv, poetry, pip), версия Go.
- Шаблон: форж (`github`, `gitea`, `gitlab`, `azure`), стеки, путь файла, параметры (текст, выбор, флаг) и тело.
  Подстановка — `{{name}}`, блоки `{{#name}}…{{/name}}` и `{{^name}}…{{/name}}`. Неизвестное имя, незакрытый блок или
  значение вне правил параметра — отказ `TEMPLATE_INVALID`. Значения — одна строка из безопасных символов, поэтому
  подстановка не ломает YAML.
- Встроенные шаблоны: Node, Python, Go, Rust, Docker (сборка образа без публикации) для GitHub Actions, Gitea Actions,
  GitLab CI и Azure Pipelines. Секретов не используют.
- Свои шаблоны: настройка «CI templates (JSON)» и папка на машине копии (`*.json`, до 50 файлов по 64 KB) в том же
  формате. Каждый шаблон проверяется: схема, подстановка с параметрами по умолчанию, отсутствие секретоподобного
  содержимого (ключи, токены известных форджей, учётные данные в адресах). Негодный шаблон показывается с причиной и
  не применяется.
- Запись: новое удалённое действие `ciFile` через существующие prepare/publish (превью с файлом, базовым коммитом и
  веткой, подтверждение, журнал Activity). Publish создаёт файл в новой ветке от головы ветки по умолчанию через API
  форджа (GitHub: ref + contents; Gitea: contents с `new_branch`; GitLab: commits с `start_sha`; Azure: pushes), затем
  открывает PR/MR. Голова базы сверяется в publish; существующая ветка или файл — отказ форджа. Если ветка создана, а
  PR нет, исход называет ветку.
- UI: кнопка «Templates» в разделе Actions; стек и признаки, список шаблонов (подходящие стеку сверху), форма
  параметров, превью файла с подсветкой, имя ветки и заголовок PR, предупреждение о существующих CI-файлах.

## Срезы

1. Ядро `src/core/ci-templates/`: стек, подстановка, проверка шаблона, каталог встроенных. Тесты на эталонах.
2. Хост: `ciStack` (пути и манифесты из `HEAD`), `ciTemplateFolder` (свои шаблоны). Тесты на временных репозиториях.
3. Провайдеры: `createFile` для четырёх форджей; удалённое действие `ciFile`; RPC `ciTemplates`. Тесты с фальшивым HTTP.
4. UI: страница шаблонов в Actions.
5. Стенд (двойник Gitea: шаблон → ветка → PR), ревью, документация, доклад.
