# Mail: MCP for outside assistants — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local stdio MCP server through which an outside assistant searches and reads mail exactly as BB's agents do, behind a switch that is off by default.

**Architecture:** The server file is plain Node source kept as a string in `src/core/mcp-server-source.ts` and saved by the settings page; it shells out to `bb makosh-mail … --assistant --json`. The CLI's assistant mode reuses the agent search and read paths, the agent log (actor `mcp`) and a setting `mcpAccess`.

**Spec:** `docs/superpowers/specs/2026-11-20-mail-mcp-design.md`

## Global Constraints

As in `docs/superpowers/plans/2026-11-20-mail-ai-sorts.md`. No new RPC method unless the settings block needs one. The server file imports only `node:` modules; `src/core` holds it as text and does not import them.

Exact values: 500-character query, 20 hits, 30 seconds, 1 MB, 60 calls an hour, setting `mcpAccess` (off), actor `mcp`.

## Review Focus

1. The assistant mode cannot reach mail outside AI access, unredacted text or an unlogged call; with `mcpAccess` off it gives nothing, not even account names.
2. The server passes arguments as an array: no shell, no injection through a query or an id; limits on time and output.
3. The protocol answers are valid MCP (ids echoed, errors as JSON-RPC errors or `isError`, nothing written to stdout but protocol lines).
4. Agent access inside BB is unchanged.
