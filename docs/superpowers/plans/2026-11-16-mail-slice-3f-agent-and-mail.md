# Makosh Mail — Slice 3f (redaction, AI access scope, agent log, summaries, Ask, tasks, categories, Today, reply reminders, draft edits) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use `- [ ]`.

**Goal:** Every text that reaches an agent or a model passes one redaction (`redactSecrets`: one-time codes, passwords, tokens, card numbers become `[hidden …]` placeholders) and one access scope (per account all folders / chosen folders / none, Spam and Trash never, excluded senders and domains over their whole correspondence); every agent tool call, mention, Hand to agent, CLI read in a thread and owner-click model call writes a content-free row to a local action log, shown in Mail settings → **Agent activity**. On the owner's click and through makosh-ai only, the plugin summarizes a conversation with citations, answers a question about the mail with linked sources (the model plans queries, the plugin searches locally), finds tasks and deadlines the owner may keep in a local **Tasks** view, suggests one of four local categories, summarizes the Today list, and rewrites the owner's own draft text behind a diff the owner applies. With `morningDigest` on, a local **Today** view (needs a reply, waiting for a reply, tasks due, counts since yesterday) is built once a day by a 60 s clock and announced by a toast outside quiet hours. A reply reminder set at send or on a Sent message turns due when no message references it within N days and shows in a **Waiting for a reply** strip. The makosh-ai adapter reads `ai.v1.providers` in its real shape and maps `<reason>: text` refusals. Nothing in 3f writes to an IMAP server or makes an HTTP request.

**Architecture:** Same layers. Core gains pure modules: `redact.ts` (detectors, `redactSecrets`, `restoreSecrets`, `hiddenNote`), `ai-scope.ts` (`inAiScope`, scope types), `agent-log.ts` (entry types, `logAgent`, outcome mapping), `ai-input.ts` (`frameInput`, `stripQuoted`, per-kind builders and parsers, `AI_MAX_OUTPUT_TOKENS`, `AI_RATES`), `text-diff.ts` (`wordDiff`), `categories.ts`, `digest.ts`, `reminders.ts`; `agent-text.ts` renderers, `templates.ts` (`templatesForAgent`) and `translate.ts` (`translationSource`, `PROMPT_VERSION` 2) call the redaction. Store gains migration element 10 (`ai_scope_accounts`, `ai_scope_senders`, `agent_log`, `ai_results`, `mail_tasks`, `message_categories`, `category_suggestions`, `category_rules`, `digests`, `reply_dismissals`, `reply_reminders`, with `notified_at` on `digests` and `reply_reminders`) and the SQL function `mail_ai_in_scope`. Adapters gain `ai-jobs.ts` and `day-clock.ts`; `makosh-ai-translator.ts` and `translate-jobs.ts` change; the sync outcome gains `inserted`. Server gains 24 owner RPCs, settings `mailCategories`, `morningDigest`, `digestTime`, `replyReminderDays`, the relabelled `translateProvider` / `translateModel`, the `mail-day` channel and scope, redaction and log on every agent path. UI gains the summary block, tasks dialog, Ask panel, category chips and filters, reminder strip, Improve dialog, Remind checkbox, Today and Tasks views, AI access and Agent activity settings, and the day notices in the badge hook.

**Spec:** `docs/superpowers/specs/2026-11-16-mail-slice-3f-agent-and-mail-design.md` — its "Resolutions after the builder check" (1–19) override every section above them; the owner accepted all decisions on 2026-11-16 and the *(owner defaults)* items as recommended. Slice 1, 2, 3a, 3b, 3c, 3d and 3e specs (with their resolutions) still hold where 3f does not change them.

## Global Constraints

- Slice-1, slice-2 and 3a–3e global constraints still bind (see `docs/superpowers/plans/2026-11-14-mail-imap-first-slice.md`, `2026-11-15-mail-folders-images-actions.md`, `2026-11-15-mail-slice-3a-organize.md`, `2026-11-15-mail-slice-3b-compose.md`, `2026-11-15-mail-slice-3c-agent-send-translate.md`, `2026-11-15-mail-slice-3d-sending-polish.md`, `2026-11-15-mail-slice-3e-inbox-triage.md`), extended. **No new server writes in 3f:** no IMAP command that writes, no folder, keyword or label, no move for reminders or categories. **No new outbound HTTP:** model calls go only through makosh-ai's plugin RPC (`callRpc`), as translation does; `src/adapters/bb/one-click.ts` stays the only HTTP client.
- **No model call without the owner's click.** No sync step, clock, toast, realtime event or agent tool starts an `ai_start` job or a makosh-ai stream. The day clock and reminders read the store only.
- **No secret reaches an agent or a model outside a core renderer or builder that calls `redactSecrets`.** Redaction runs over the whole field before any cut (spec resolution 5). Restore maps (translation, draft edits) live in job memory only, never sent, logged, stored or published.
- **No mail content in the action log, logs, realtime or errors.** `agent_log` holds ids (≤ 50), counts, tool and outcome codes, timestamps, the thread id, the provider and model setting values — never a query, question, instruction, subject, name, address, snippet, result or error text. `mail-day` carries `{ token }` only. Raw model output is never shown, logged or stored.
- **Model output is text.** Rendered with `white-space: pre-wrap` through `revealHidden`, never as HTML or Markdown, links not clickable; only the plugin's own citation chips (indexes the plugin mapped to ids it sent) are interactive. Nothing a model returns labels, keeps, sends or applies anything without the owner's click.
- **Nothing runs without the owner.** No agent tool sets a category, keeps a task, sets a reminder or edits a draft. Every 3f write RPC refuses plugin callers (`refusePluginCaller`); `ai_start` is owner-only and capped per kind (`AI_RATES`).
