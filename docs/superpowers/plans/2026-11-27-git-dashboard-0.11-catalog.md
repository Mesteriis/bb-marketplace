# Makosh Git 0.11 — каталог проектов

Ветка `feature/bb-git-dashboard-catalog` от main 84aeaa65. Дизайн: строка 0.11.0 и §12 («настоящие проекты»). Перенос из GitWand `gitwand/v0.2.0`: `core/git-remotes.ts` (ключ репозитория по адресу remote, чтение remote из `.git/config`) и `core/repo-catalog.ts` (объединение локальных и удалённых, отметка «клонирован», сохранение прошлого списка источника при ошибке). Список удалённых берётся не из gh/glab, как в GitWand, а через API подключённых аккаунтов всех четырёх форджей (`Provider.repositories`).

## Решения

- Локальные проекты — обход «Папки проектов» на выбранной машине по правилам §12 (уже есть с 0.2). Для каждого проекта хост читает адреса remote из `.git/config` (без запуска git). SSH-алиас без точки в имени хоста раскрывается через `ssh -G`, как при автоподключении.
- «Клонирован»: удалённый репозиторий, чей ключ `host/путь` совпадает с ключом remote локального проекта. Один репозиторий, видимый двум аккаунтам, — одна строка.
- Клон по клику: окно спрашивает каждый раз машину, категорию (папку внутри «Папки проектов», например `Personal` или `Work/<группа>`) и имя. Клон идёт существующим путём — превью и подтверждение, HTTPS с учётными данными аккаунта.
- Групповые действия по отмеченным локальным проектам: статус (ветка, впереди / позади, изменения) — чтение; fetch и pull (только fast-forward) — после подтверждения со списком проектов. Работают только с проектами внутри «Папки проектов» на этой машине; хост сам проверяет, что путь лежит внутри неё.
- Fetch и pull по SSH: у владельца remote в основном SSH. Сейчас git плагина запрещает все протоколы, кроме file и HTTPS аккаунта. Для групповых fetch и pull разрешается `ssh` с `BatchMode=yes` (никаких вопросов, только ключи и агент пользователя, `SSH_AUTH_SOCK`), без хуков и без сабмодулей. Для HTTPS-адресов — учётные данные подключённого аккаунта, как в существующем fetch.
- «PR по выбранным»: открытые PR отмеченных удалённых репозиториев (просмотр, как в GitWand), без массового создания.

## Срезы

1. Ядро `src/core/catalog/`: ключ remote, чтение remote из config, объединение каталога, категории из дерева проектов, путь клона. Тесты на эталонах (перенесённые из GitWand и новые).
2. Хост: `catalogLocal` (проекты с remote), `catalogGit` (status, fetch, pull в пределах «Папки проектов»). Тесты на временных репозиториях.
3. Сервер: RPC `catalog` (локальные с машины плюс удалённые со всех аккаунтов, с кешем), `catalogBulk`, `catalogPulls`.
4. UI: страница «Каталог» в шапке Git; фильтры, отметки, групповые действия, окно клона.
5. Стенд (двойники Gitea и GitLab), ревью, документация, доклад.
