# Makosh Git 0.10 — merge, rebase и редактор конфликтов

Ветка `feature/bb-git-dashboard-merge` от main f2336832. Дизайн: `docs/superpowers/specs/2026-11-27-unified-git-plugin-design.md`, строка 0.10.0 и п. 7 («merge/rebase/abort/continue с approval; редактор конфликтов: ours/theirs/base, построчный выбор, ручная правка»). Rebase только обычный, без интерактивного.

## Решения

- Git на хосте запускается как сейчас (`git-process.ts`): без хуков, без глобального конфига, автор берётся из локального конфига или вводится в форме, как у коммита. Добавляются `GIT_EDITOR=true` и `GIT_SEQUENCE_EDITOR=true`: ни одна команда не ждёт редактора. Маркеры конфликтов пишутся в стиле `zdiff3`, чтобы и внешний редактор видел base.
- Каждая запись (merge, rebase, abort, continue, skip, сохранение решения) идёт через окно подтверждения с превью. В превью merge и rebase заранее сказано, сколько коммитов придёт и какие файлы будут в конфликте: `git merge-tree --write-tree --name-only` (рабочее дерево не трогается).
- Merge и rebase стартуют только на чистом дереве и только при том HEAD, который видел пользователь (`expected`, иначе STALE_HEAD).
- Редактор конфликтов строит тройку ours / base / theirs из стадий индекса (`:1:`, `:2:`, `:3:`) через `git merge-file -p --zdiff3` на временных файлах. Поэтому правки в рабочем файле не мешают разбору. Сохранение пишет текст с проверкой хеша, как Apply suggestion, и делает `git add`. Текст с оставшимися маркерами не сохраняется как решённый.
- Конфликты «удалён у одной стороны», бинарные файлы и сабмодули в редакторе не правятся. Для них — «Взять ours / theirs / удалить» целиком (`git checkout --ours/--theirs`, `git rm`).
- Агентам merge и rebase не даются (инструменты агентов не меняются). Тред, работающий в копии, увидит конфликт обычными средствами git.

## Срезы

1. Ядро `src/core/merge/`: разбор маркеров (merge, diff3, zdiff3), модель решения (ours, theirs, оба порядка, base, построчный выбор, ручной текст), сборка итогового текста; состояние последовательности (merge или rebase, шаг N из M, конфликтные файлы). Тесты на эталонах.
2. Хост: действия `sequence`, `mergePreview`, `conflict` (чтение), `merge`, `rebase`, `abort`, `continue`, `skip`, `resolve`, `take` (запись) в `gitAction` и `local-git.ts` (вынести в `merge-git.ts`). Тесты на временных репозиториях с настоящими конфликтами.
3. UI: Merge… и Rebase onto… у веток (Branches), окно подтверждения с превью; полоса «Идёт merge / rebase» с Abort, Continue, Skip и списком конфликтных файлов; редактор конфликтов `src/ui/merge/`.
4. Стенд: проба на репозитории с конфликтом (merge и rebase, решение в редакторе, continue, abort). Живая проверка на песочницах (GitHub PR #2, GitLab MR !2): локальный merge base в ветку PR и разбор конфликта, без push.
5. Ревью (Opus), документация (CHANGELOG, версия 0.10.0, PLUGIN_OVERVIEW, навык не меняется), доклад.
