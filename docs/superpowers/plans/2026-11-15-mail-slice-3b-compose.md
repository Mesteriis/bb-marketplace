# Makosh Mail — Slice 3b (compose, send, reply) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use `- [ ]`.

**Goal:** Compose, Reply, Reply all and Forward with a rich-text editor and attachments; drafts saved locally and copied to the account's Drafts folder; sending over SMTP through an outbox with a 10 s Undo, owner-driven Retry and never a silent drop or a double send; a Sent copy where the server does not keep one; SMTP settings on every account.

**Architecture:** Same layers. Core gains pure compose logic (addresses, reply rules, subjects, the editor document schema and renderer, the Bcc splice), the outbox state machine and the compose use cases over new ports (`MailTransport`, `MessageBuilder`, `OriginalReader`, `AccountWriteQueue`, `OutboxNotifier`) and new `FolderSession` / `MailStore` methods. Store gains migration element 4 (SMTP columns, `messages.reply_to_json`, `compose_drafts`, `compose_attachments`, `outbox`). Adapters gain imapflow APPEND / SEARCH HEADER / guarded single-uid UID EXPUNGE, a per-account write queue, nodemailer `MailComposer` and SMTP transport, chunked upload sessions and an outbox worker inside the existing background service. UI gains the TipTap composer, recipient chips, the outbox section and SMTP settings; toasts stay in `app.tsx`.

**Spec:** `docs/superpowers/specs/2026-11-15-mail-slice-3b-compose-design.md` — its "Resolutions after the builder check" override every section above them; the owner approved all *(owner)* items in the recommended form on 2026-11-15. Slice 1, 2 and 3a specs still hold where 3b does not change them.

## Global Constraints

- Slice-1, slice-2 and 3a global constraints still bind (see `docs/superpowers/plans/2026-11-14-mail-imap-first-slice.md`, `2026-11-15-mail-folders-images-actions.md`, `2026-11-15-mail-slice-3a-organize.md`), extended. Server writes allowed in 3b = the 3a set plus: SMTP submission of a message the owner sent; APPEND to Drafts (only on servers with UIDPLUS) and to Sent (only for `sent_copy = 'append'` accounts); `STORE +FLAGS \Deleted` followed by `UID EXPUNGE <uid>` of exactly one uid that came from our own APPENDUID or is the one foreign draft the owner continued, after a Message-ID + `RFC822.SIZE` guard fetch, UIDVALIDITY unchanged, UIDPLUS checked by the gateway before any command. Never a plain `EXPUNGE`, never `messageDelete` without UIDPLUS, never `\Deleted` without the expunge that follows it.
- **Sending is owner-initiated and irreversible.** Only the owner's Send click or Cmd/Ctrl+Enter queues a message. Sync, restarts, realtime, mentions, CLI and agents never queue or resend. Once DATA may have been accepted there is no automatic resend; the only automatic retry is the idempotent Sent APPEND (search by Message-ID first, at most 3 tries). Accepted limit (resolution 1): `refusePluginCaller` refuses only `kind: "plugin"`, so a `client` caller with shell access can still call local RPC; mitigations are mandatory — every queued send publishes `outbox-changed` and any open Mail page shows its Undo toast, the Outbox is always reachable, 10 sends per minute per account.
- **No secrets or content in logs, realtime, errors or agent text.** Never the password, SMTP response text, recipients, subjects, file names, message bodies or attachment bytes. Errors carry `errorKind` / `SendErrorKind` only; realtime carries account ids, outbox ids and states only. nodemailer `logger` and `debug` stay off. The password is unsealed for one SMTP session and dropped.
- **Agents get nothing in 3b.** No new agent tool, CLI command, mention provider or skill capability; every new RPC is registered with `{ experimental_discoverable: false }` and starts with `refusePluginCaller(context)`. `origin` is always `"owner"` (the column and `queueSend(…, { origin })` are the 3c seam only). Drafts synced from the server stay ordinary Drafts messages to `mail_search`, and the docs say so.
- MIGRATIONS: elements 0–3 frozen (shipped, hash-pinned by BB). Append element 4 only; never edit or reformat an earlier element. New tables keep ISO TEXT timestamps.
- `src/core` and `src/ui` stay host-free. The `ui` allow-list in `tests/architecture.test.ts` gains exactly `"@tiptap/react"`, `"@tiptap/core"`, `"@tiptap/pm"`, `"@tiptap/starter-kit"` — never `"@tiptap"`; `core` gains nothing. `src/ui` never imports `sonner`.
- Dependencies (resolution 18): `nodemailer` and the four TipTap packages at **exact** pins (`nodemailer` 10.3.1, TipTap 3.32.2 — re-check at install that each is at least two weeks old); nothing vendored, so `THIRD_PARTY_NOTICES.md` is untouched unless code is ported. Run `node ../../scripts/check-manifests.mjs` after every `package.json` change.
- HTML: the server never accepts HTML from the page; it renders message HTML itself from the validated document. Quoted or imported HTML passes `sanitizeEmailHtml` (remote images off) and loses every `<img>` before TipTap parses it. The editor never loads a remote resource.
- Headers: CR, LF and NUL refused in every header input at the zod boundary and again in the builder; non-ASCII local parts refused (no SMTPUTF8); domains punycoded in core; `MailComposer` is the only header writer; attachments passed by `content` only, never `path`/`href`.
- Tests colocated next to the code (`*.test.ts(x)`); fixtures use made-up addresses on `example.com` / `example.org` and made-up text only.
- Every task leaves `npm run check` green and is committed on `feat/mail-imap-slice` with the trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. `git add` only the task's own files (the tree holds unrelated uncommitted changes). Never push, tag or publish; never touch the installed plugin or `.worktrees/live`.

## Review Focus

- **Double send:** the same `requestId` twice, a double click, a tick racing Undo, two worker ticks, a restart while `sending` — at most one SMTP submission, `sending` becomes `unknown` on start, Retry refused for `unknown`. Tests in Tasks 3, 4 and 7.
- **Post-DATA classification:** a 5xx after DATA → `failed`/`rejected_message`; 4xx anywhere → `failed`/`temporary`; no reply after DATA (timeout, socket close, abort) → `unknown`; nothing after DATA is ever `connect`/`timeout_before_data`. Tests in Task 5.
- **Expunge safety:** without UIDPLUS `expungeOwn` throws before any command and `messageDelete` / `messageFlagsAdd` are never called; a guard mismatch (Message-ID or size) refuses; only uids from our APPENDUID or the continued foreign draft ever reach it; APPEND failure deletes nothing. Tests in Tasks 3 and 5.
- **Bcc:** the SMTP bytes contain no `Bcc:`; the Sent copy differs from them by exactly one folded ASCII `Bcc:` line; drafts keep Bcc. Tests in Tasks 1 and 5.
- **Header and HTML injection / path traversal:** CR/LF/NUL/`%0d%0a` in subject, names, addresses; hostile quoted HTML (`<script>`, `onerror`, `javascript:`, `<style>`, `srcset`, `<svg>`, `<form>`, `<base>`, CSS `url()`, remote `<img>`); file names `../../x`, `/etc/passwd`, `C:\x`, control/bidi characters. Tests in Tasks 1, 5, 7 and 8.
- **Reply-all recipients:** the table in Task 1, including every connected account's addresses removed and Bcc never carried.
- **Lost text:** the local row is written before any server step; revision CAS gives `conflict` to a stale tab and while a send is queued; Undo restores fields, doc and attachments exactly. Tests in Tasks 3, 4 and 9.
