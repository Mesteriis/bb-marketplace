# Makosh Git 0.13 — скаффолды

Ветка `feature/bb-git-dashboard-scaffolds` от main af13c205. Дизайн: строка 0.13.0, §13.4 и §13.5 (утверждённый список и
общий набор файлов). Требования к содержимому — разбор лучших практик по каждому скаффолду (правила владельца главнее
документации, документация главнее привычек). Деление на три подсреза принято родительским тредом.

## Общее

- Скаффолд — шаблон с параметрами, набором файлов (путь и тело — шаблоны 0.12, файл может зависеть от флага или
  выбора), строками `.gitignore` и секциями `.editorconfig` своего стека, и значениями CI-шаблона из 0.12.
- Свободный текст (описание, автор) — параметр вида «строка»: одна строка без управляющих символов. В Markdown и
  простой текст подставляется как есть, в TOML, JSON и YAML только фильтром `{{name|json}}` (строка в кавычках с
  экранированием), иначе отказ `TEMPLATE_INVALID`.
- Общий набор: LICENSE (MIT, Apache-2.0 или без лицензии), SECURITY.md, README.ru.md, AGENTS.md и CLAUDE.md
  (`@AGENTS.md`), .editorconfig, .gitattributes, .gitignore (с `.env*` кроме `.env.example` и `.zed/`), CHANGELOG.md
  (Keep a Changelog), THIRD_PARTY_NOTICES.md; CONTRIBUTING.md и CODE_OF_CONDUCT.md — флажками. `zed-init` плагин не
  запускает (локальный инструмент владельца, плагин публичный).
- Проверки результата: путь относительный, без `..`, не в `.git/`, никаких `.env` кроме `.env.example`; в тексте нет
  ключей, токенов, учётных данных в адресах и IP-адресов. Публичные адреса документации и лицензий допустимы.
- Версии инструментов — в одном манифесте версий ядра, не по файлам.

## 0.13.0 — движок и первые три скаффолда

1. Ядро `src/core/scaffolds/`: модель, рендер (поверх рендера 0.12), общий набор, манифест версий, скаффолды
   python-service-uv (варианты plain и FastAPI, Docker флажком), bb-plugin, go-service-with-web (web и Docker флажками).
   Стек созданных файлов определяется кодом 0.12, и к ним добавляется CI-файл выбранного форжа.
2. CI-шаблоны 0.12: Corepack ставится явно (`npm install -g corepack`), потому что Node 25+ его не поставляет; у
   Python с uv флаг lockfile (`uv sync --locked` только при закоммиченном `uv.lock`); флаг make — CI вызывает
   `make check`, если в корне есть Makefile с целью `check` (ADR-011).
3. Хост `scaffoldCreate`: папка `<Папка проектов>/<категория>/<имя>` (только внутри, родитель существует, папки нет),
   файлы без ссылок, `git init -b main`, первый коммит с автором из формы; при сбое созданная папка удаляется.
4. Сервер: RPC списка скаффолдов, превью (файлы, место, шаги) и создания после подтверждения; копия регистрируется в Git.
5. UI: «Новый проект…» в Каталоге: скаффолд, категория, имя, параметры, CI-форж, автор, список файлов с просмотром.
6. Стенд: скаффолд → папка с первым коммитом на машине. Ревью, документация, доклад.

## 0.13.1 — репозиторий на форже и первый push

Приватный по умолчанию (публичный — только явным выбором, виден в превью); создание на GitHub, GitLab, Gitea и Azure;
origin и первый push тем же путём учётных данных, что HTTPS fetch 0.11 (токен не в URL, не в `.git/config`, не в
аргументах). Двойник Gitea отдаёт git по HTTPS через `git http-backend`. Живой скрипт с временным приватным
репозиторием `makosh-git-scaffold-live-<stamp>` запускает родительский тред после согласия владельца.
